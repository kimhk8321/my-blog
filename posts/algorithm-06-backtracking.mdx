입력이 작으면 가능한 답을 전부 만들어 보는 풀이가 가장 명확할 때가 있습니다. 다만 “작다”를 감으로 판단하면 안 됩니다. 원소가 n개일 때 부분집합은 2ⁿ개, 순열은 n!개입니다. 무엇을 만드는 문제인지부터 계산해 봅니다.

백트래킹은 답을 만드는 도중 조건을 만족할 수 없는 가지를 멈추는 방식입니다. 가지치기를 넣기 전에, 우선 모든 유효한 답을 방문하는 탐색을 만들어야 합니다.

## 조합의 합: 선택 순서를 고정한다

양의 정수 후보를 여러 번 사용해 target을 만드는 조합을 구합니다. `[2, 3]`과 `[3, 2]`는 같은 조합입니다. target은 0 이상입니다. 후보에 중복 값이 들어와도 결과는 중복 없이 반환합니다.

```js
function combinationSum(candidates, target) {
  const values = [...new Set(candidates)].sort((a, b) => a - b);
  const answer = [];
  const path = [];

  function search(start, remaining) {
    if (remaining === 0) {
      answer.push([...path]);
      return;
    }
    for (let i = start; i < values.length; i++) {
      if (values[i] > remaining) break;
      path.push(values[i]);
      search(i, remaining - values[i]);
      path.pop();
    }
  }

  search(0, target);
  return answer;
}

console.log(combinationSum([2, 3, 6, 7], 7));
```

답은 `[[2, 2, 3], [7]]`입니다. 다음 선택의 시작 위치를 i로 두어 같은 값을 다시 쓸 수 있게 합니다. `i + 1`이면 각 후보를 한 번만 사용하는 다른 문제가 됩니다.

start 이전 후보로 돌아가지 않으므로 `[3, 2, 2]` 같은 순서만 다른 결과가 생기지 않습니다. 정렬돼 있고 후보가 양수라서 현재 값이 남은 합보다 크면 이후 후보도 모두 실패합니다. 그래서 `continue`보다 강한 `break`를 쓸 수 있습니다.

0을 허용하면 같은 상태를 무한히 재귀 호출하고, 음수를 허용하면 remaining이 계속 줄어든다는 보장도 사라집니다. 이 가지치기를 그대로 쓰려면 **양수라는 전제**가 필요합니다.

## path를 복사하지 않으면 결과가 사라진다

정답에 `path` 자체를 넣으면 이후 `pop()`이 이미 저장한 답까지 바꿉니다. 서로 다른 결과처럼 보여도 같은 배열 참조일 수 있어요. `answer.push([...path])`로 그 시점의 경로를 복사합니다.

불변식은 “search에 들어왔을 때 path의 합과 remaining의 합이 원래 target이다”입니다. 선택 후에는 반드시 해제해서 다음 형제 가지가 같은 출발 상태를 갖게 합니다.

## 중복 원소가 있는 순열

`[1, 1, 2]`의 서로 다른 순열은 세 개입니다. Set에 결과 문자열을 쌓아 나중에 중복을 지울 수도 있지만, 중복된 탐색 자체를 막는 편이 낫습니다.

```js
function uniquePermutations(nums) {
  const values = [...nums].sort((a, b) => a - b);
  const used = Array(values.length).fill(false);
  const answer = [];
  const path = [];

  function search() {
    if (path.length === values.length) {
      answer.push([...path]);
      return;
    }
    for (let i = 0; i < values.length; i++) {
      if (used[i]) continue;
      if (i > 0 && values[i] === values[i - 1] && !used[i - 1]) continue;
      used[i] = true;
      path.push(values[i]);
      search();
      path.pop();
      used[i] = false;
    }
  }

  search();
  return answer;
}

console.log(uniquePermutations([1, 1, 2]));
```

`!used[i - 1]`은 같은 깊이에서 앞의 동일 값을 선택하지 않은 상태라는 뜻입니다. 같은 깊이에서는 왼쪽의 1부터 선택하게 만들어 중복 분기를 막습니다. 앞의 1이 이미 경로에 사용된 상태라면 두 번째 1도 선택할 수 있어야 합니다. 조건에서 `used`를 빼면 `[1, 1, 2]` 자체를 만들지 못합니다.

## 가지치기했다고 다항 시간이 되지는 않는다

순열은 중복이 없는 최악의 경우 답만 n!개이고 각 답을 복사하는 데 O(n)이 필요하므로 전체 시간 O(n × n!) 수준입니다. 결과 저장을 제외한 경로·방문 배열·재귀 깊이는 O(n)입니다.

조합의 합은 후보 수 m, 가장 작은 후보 a, 깊이 상한 D = floor(target / a)로 보면 탐색 노드 수가 대략 `1 + m + ... + m^D` 이하라는 보수적인 상한을 잡을 수 있습니다. 각 노드의 후보 순회와 결과 복사 비용도 고려해야 합니다. 실제 방문 수는 정렬·start·합 제한으로 줄지만 여전히 지수적으로 늘 수 있습니다. 후보가 비면 이 깊이 계산 대신 즉시 빈 결과 여부를 판단하면 됩니다.

최소한 아래를 확인합니다.

- 후보 `[2]`, target 3: 만들 수 없으면 빈 배열인가?
- 후보 `[2, 2, 3]`, target 7: 같은 조합을 중복 반환하지 않는가?
- target 0: 아무것도 선택하지 않은 `[[]]`를 반환하는 규칙인가?
- 순열 `[1, 1, 1]`: 결과가 정확히 하나인가?
- 입력 배열을 정렬하며 원본까지 바꾸지 않았는가?

백트래킹이 느리면 무조건 더 강한 조건을 넣기보다 그 조건으로 **정답도 같이 잘라내는지**를 먼저 의심해야 합니다. 다음 [그리디 편](/posts/algorithm-07-greedy)에서는 여러 선택을 탐색하지 않고 하나만 골라도 되는 근거를 보겠습니다.
