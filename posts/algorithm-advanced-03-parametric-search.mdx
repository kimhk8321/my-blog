[기본 이분 탐색](/posts/algorithm-04-binary-search)에서는 정렬된 배열의 값을 찾았습니다. 이번에는 **걸리는 시간 자체**를 후보로 놓고 가장 작은 답을 찾습니다. 기본 구현의 반복보다 이 응용의 기준을 이해하는 데 집중하겠습니다.

## 세 명을 심사하는 데 몇 분이 필요할까?

한 심사관은 한 명에 2분, 다른 심사관은 3분이 걸립니다. 두 사람은 동시에 일할 수 있고, 손님 세 명이 시간 0부터 기다립니다.

```text
2분 심사관: 0~2분 첫 손님, 2~4분 다음 손님
3분 심사관: 0~3분 첫 손님
```

3분까지는 두 명만 끝납니다. 4분이면 세 명이 끝나므로 최소 시간은 **4분**입니다.

## 이 시간 안에 가능한지를 먼저 계산한다

4분 안에 한 심사관이 끝낼 수 있는 사람 수는 `Math.floor(4 / 심사 시간)`입니다. 2분 심사관은 2명, 3분 심사관은 1명입니다.

```js
function countProcessed(limit, times) {
  let total = 0;
  for (const time of times) {
    total += Math.floor(limit / time);
  }
  return total;
}

console.log(countProcessed(3, [2, 3]));
console.log(countProcessed(4, [2, 3]));
```

출력은 2와 3입니다. 필요한 사람이 세 명이면 이 합계가 3 이상인지 비교하면 됩니다.

| 시간 후보 | 처리 가능 인원 | 세 명 가능? |
| --- | --- | --- |
| 2분 | 1명 | 아니오 |
| 3분 | 2명 | 아니오 |
| 4분 | 3명 | 예 |
| 5분 | 3명 | 예 |
| 6분 | 5명 | 예 |

시간을 더 줬는데 처리할 수 있는 사람이 줄어들지는 않습니다. 즉, 판정은 **불가능하다가 한 번 가능해지면 계속 가능**합니다. 이 성질을 단조성이라고 부릅니다.

## 가운데 시간을 보고 범위를 버린다

첫 번째 심사관 혼자 세 명을 처리해도 6분이면 됩니다. 그러므로 0~6분 안에 답이 있습니다. 상한은 가장 빠른 심사관을 따로 찾지 않고 `times[0] * n`으로 잡겠습니다. 이 시간에는 첫 심사관 혼자서도 모두 처리할 수 있습니다.

| 범위 | 가운데 시간 | 판정 | 남길 범위 |
| --- | --- | --- | --- |
| `[0,6]` | 3 | 두 명이라 불가능 | `[4,6]` |
| `[4,6]` | 5 | 세 명이라 가능 | `[4,5]` |
| `[4,5]` | 4 | 세 명이라 가능 | `[4,4]` |

불가능한 3분과 그보다 짧은 시간은 모두 버립니다. 가능한 5분은 답일 수도 있지만 더 작은 답이 있을 수 있어 왼쪽을 계속 찾습니다. 그래서 **가능하면 mid도 남기고, 불가능하면 mid까지 버립니다.**

## 전체 JS 코드

위 원리를 일반 숫자로 구현합니다. 앞에서 만든 `countProcessed` 함수와 함께 실행하면 됩니다. 가운데 시간도 정수여야 하므로 `Math.floor`로 소수 부분을 버립니다.

```js
function minimumInspectionTime(n, times) {
  let left = 0;
  let right = times[0] * n;
  while (left < right) {
    const mid = left + Math.floor((right - left) / 2);
    const processed = countProcessed(mid, times);

    if (processed >= n) right = mid;
    else left = mid + 1;
  }
  return left;
}

console.log(minimumInspectionTime(3, [2, 3]));
```

출력은 `4`입니다. processed는 mid분 동안 처리할 수 있는 사람 수입니다. 이 값이 n 이상이면 가능한 시간입니다. `left`와 `right`는 아직 답일 수 있는 시간 범위이고, 두 값이 같아지면 최소 시간을 찾은 것입니다.

## 기본 이분 탐색과 다른 부분

배열에 4가 들어 있는지를 찾는 게 아닙니다. **4분 안에 세 명을 처리할 수 있는지**를 계산합니다. 이처럼 '최솟값을 찾아라'를 '이 값으로 가능한가?'로 바꾸는 응용을 매개변수 탐색이라고도 부릅니다.

가능 여부가 제멋대로 바뀐다면 이 방식으로 구간을 버릴 수 없습니다. 먼저 판정이 한 방향으로 바뀌는지 확인해야 합니다.

## 복잡도와 입력 범위

심사관 m명과 시간 상한 U에 대해 시간 후보를 하나씩 검사하면 O(mU), 이분 탐색하면 O(m log(U + 1))입니다. 추가 공간은 O(1)입니다.

n은 음수가 아닌 정수이고 times에는 양의 정수인 심사 시간이 하나 이상 있다고 가정합니다. 이 코드는 원리를 익히기 위한 예제로, 시간 상한과 처리 인원 등 계산하는 정수가 `Number.MAX_SAFE_INTEGER` 이내인 입력을 다룹니다. [원문 입국심사 문제](https://school.programmers.co.kr/learn/courses/30/lessons/43238)의 최대 입력은 이 범위를 넘을 수 있습니다.
