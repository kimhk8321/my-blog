격자 문제를 보면 이차원 배열부터 보이지만, 갈 수 있는 칸을 정점으로 보고 인접한 이동을 간선으로 보면 그래프입니다. 탐색에서 먼저 정할 것은 자료구조보다 **상태 하나가 무엇인지**입니다.

좌표만 같으면 같은 상태일까요? 벽을 한 번 부술 수 있는 문제라면 `(행, 열, 남은 벽 파괴 횟수)`까지 같아야 같은 상태입니다. 방문 배열이 무엇을 구별하는지부터 분명해야 합니다.

## 같은 비용의 이동이면 BFS

0은 통로, 1은 벽인 직사각형 격자에서 왼쪽 위부터 오른쪽 아래까지의 최소 이동 횟수를 구합니다. 시작 칸은 거리 0이고, 도착할 수 없으면 -1입니다.

```js
function shortestGridPath(grid) {
  const rows = grid.length;
  const cols = grid[0]?.length ?? 0;
  if (rows === 0 || cols === 0) return -1;
  if (grid[0][0] === 1 || grid[rows - 1][cols - 1] === 1) return -1;

  const distance = Array.from({ length: rows }, () => Array(cols).fill(-1));
  const queue = [[0, 0]];
  let head = 0;
  distance[0][0] = 0;
  const moves = [[1, 0], [-1, 0], [0, 1], [0, -1]];

  while (head < queue.length) {
    const [r, c] = queue[head++];
    if (r === rows - 1 && c === cols - 1) return distance[r][c];

    for (const [dr, dc] of moves) {
      const nr = r + dr;
      const nc = c + dc;
      if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;
      if (grid[nr][nc] === 1 || distance[nr][nc] !== -1) continue;
      distance[nr][nc] = distance[r][c] + 1;
      queue.push([nr, nc]);
    }
  }
  return -1;
}

console.log(shortestGridPath([[0, 0, 0], [1, 1, 0], [0, 0, 0]]));
console.log(shortestGridPath([[0]]));
```

결과는 `4`, `0`입니다. “방문한 칸 수”를 답으로 요구하는 문제라면 시작 거리를 1로 두어야 합니다. 문제의 거리 정의를 코드와 맞추는 게 첫 번째 확인 사항입니다.

## 방문 처리는 큐에 넣을 때

두 정점 A와 B가 둘 다 C로 이어진다고 해 봅시다. C를 꺼낼 때 방문 처리하면 A와 B가 처리되는 동안 C가 중복으로 큐에 들어갈 수 있습니다. 큐에 넣는 순간 거리를 기록하면 정점 하나가 한 번만 등록됩니다.

BFS 큐는 거리가 작은 순서대로 처리됩니다. 거리 d인 칸에서 새로 등록한 이웃의 거리는 d + 1입니다. 따라서 처음 등록한 거리가 최단 거리입니다. 이 설명은 **모든 간선 비용이 같을 때** 성립합니다. 비용이 다른 그래프는 [10편의 다익스트라](/posts/algorithm-10-graph)를 검토해야 합니다. [BFS의 최단 경로 조건](https://cp-algorithms.com/graph/breadth-first-search.html)도 이 구분을 전제로 합니다.

일반 그래프는 인접 리스트 기준 O(V + E), 격자는 네 방향만 확인하므로 O(rows × cols)입니다. 거리 배열과 큐의 추가 공간도 O(rows × cols)입니다. 인접 행렬 전체를 매번 훑는 구현에는 O(V + E)를 그대로 붙일 수 없습니다.

## 연결 요소만 필요하면 DFS로도 충분하다

무방향 그래프에서 연결된 덩어리 수를 구합니다. 정점 번호는 0부터 n - 1까지이며 고립 정점도 하나의 요소입니다.

```js
function countComponents(n, edges) {
  const graph = Array.from({ length: n }, () => []);
  for (const [a, b] of edges) {
    graph[a].push(b);
    graph[b].push(a);
  }
  const visited = Array(n).fill(false);
  let count = 0;

  for (let start = 0; start < n; start++) {
    if (visited[start]) continue;
    count++;
    const stack = [start];
    visited[start] = true;

    while (stack.length > 0) {
      const node = stack.pop();
      for (const next of graph[node]) {
        if (visited[next]) continue;
        visited[next] = true;
        stack.push(next);
      }
    }
  }
  return count;
}

console.log(countComponents(5, [[0, 1], [1, 2], [3, 4]]));
console.log(countComponents(3, []));
```

답은 2와 3입니다. 한 번의 탐색이 끝나도 아직 방문하지 않은 시작점이 있다면 새 덩어리입니다. 이 코드는 도달 가능성만 필요해서 방문 시점에 스택에 넣습니다. 재귀 DFS와 정확히 같은 방문 순서를 재현하거나 진입·종료 시각을 구하려는 코드는 별도 상태가 필요할 수 있습니다.

시간은 O(V + E), 그래프 저장까지 포함한 추가 공간도 O(V + E)입니다. 재귀로 길게 이어진 그래프를 탐색하면 JavaScript 호출 스택 한도에 걸릴 수 있어 반복 스택을 사용했습니다.

## visited를 되돌리는 문제도 있다

연결 요소나 최단 거리는 한 번 발견한 상태를 다시 처리하지 않습니다. 하지만 서로 다른 경로를 모두 만드는 문제에서는 현재 경로에서만 사용 여부를 표시하고, 돌아올 때 해제해야 합니다. 전역 방문과 경로별 방문을 섞으면 가능한 답을 지워 버립니다.
