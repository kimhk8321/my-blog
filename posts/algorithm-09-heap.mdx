새로운 값이 계속 들어오는 동안 최솟값을 반복해서 꺼내야 한다면 매번 정렬하는 건 아깝습니다. 필요한 것은 전체 정렬 순서가 아니라 **현재 가장 우선인 값 하나**입니다.

일반적인 JavaScript 표준 내장 컬렉션에는 우선순위 큐가 없으므로 여기서는 직접 이진 힙을 만들겠습니다. 채점 플랫폼에서 별도 큐 라이브러리를 제공하더라도 어떤 순서로 비교하는지는 확인해야 합니다.

## 힙의 배열은 정렬된 배열이 아니다

0부터 시작하는 배열에서 i의 부모는 `floor((i - 1) / 2)`, 왼쪽 자식은 `2i + 1`, 오른쪽은 `2i + 2`입니다.

최소 힙은 모든 부모가 자식보다 작거나 같다는 조건만 유지합니다. 형제끼리의 순서는 보장하지 않습니다. 따라서 배열을 그대로 순회해서 정렬 결과라고 사용하면 안 됩니다.

비교 함수는 첫 인자가 더 우선이면 음수, 같으면 0, 덜 우선이면 양수를 반환하도록 정합니다.

```js
class BinaryHeap {
  constructor(compare = (a, b) => a - b) {
    this.data = [];
    this.compare = compare;
  }
  get size() {
    return this.data.length;
  }
  peek() {
    return this.data[0];
  }
  push(value) {
    const data = this.data;
    data.push(value);
    let index = data.length - 1;
    while (index > 0) {
      const parent = Math.floor((index - 1) / 2);
      if (this.compare(data[index], data[parent]) >= 0) break;
      [data[index], data[parent]] = [data[parent], data[index]];
      index = parent;
    }
  }
  pop() {
    const data = this.data;
    if (data.length === 0) return undefined;
    const root = data[0];
    const last = data.pop();
    if (data.length === 0) return root;
    data[0] = last;
    let index = 0;

    while (true) {
      const left = index * 2 + 1;
      const right = left + 1;
      let best = index;
      if (left < data.length && this.compare(data[left], data[best]) < 0) best = left;
      if (right < data.length && this.compare(data[right], data[best]) < 0) best = right;
      if (best === index) break;
      [data[index], data[best]] = [data[best], data[index]];
      index = best;
    }
    return root;
  }
}

const heap = new BinaryHeap();
for (const value of [5, 1, 4, 1, 3]) heap.push(value);
const ordered = [];
while (heap.size > 0) ordered.push(heap.pop());
console.log(ordered);
```

결과는 `[1, 1, 3, 4, 5]`입니다. 삽입은 새 원소를 부모와 바꾸며 위로 올리고, 제거는 마지막 원소를 루트에 옮긴 뒤 더 우선인 자식 쪽으로 내립니다. 트리 높이가 O(log n)이라 push·pop도 O(log n), peek는 O(1)입니다. 한 원소만 있을 때는 마지막 값을 루트에 다시 쓰면 안 됩니다.

배열 push의 일반적인 분할 상환 비용을 가정한 분석이며, 값 n개를 이 방법으로 하나씩 넣으면 O(n log n)입니다. 아래 부모부터 내려 보내는 별도의 heapify를 구현하면 O(n)에 만들 수 있지만 이 글의 생성자는 그 기능을 제공하지 않습니다.

## 큰 값 k개만 남기기

전체 n개를 정렬하지 않고 가장 큰 k개를 유지합니다. k는 0 이상인 정수이며, 반환값은 큰 순서입니다.

```js
function largestK(nums, k) {
  if (k === 0) return [];
  const heap = new BinaryHeap();
  for (const value of nums) {
    heap.push(value);
    if (heap.size > k) heap.pop();
  }
  const result = [];
  while (heap.size > 0) result.push(heap.pop());
  return result.reverse();
}

console.log(largestK([4, 1, 7, 7, 2, 9], 3));
```

답은 `[9, 7, 7]`입니다. 가장 큰 값을 구하는데 **최소 힙**을 쓰는 점이 처음에는 헷갈립니다. 남겨 둔 후보 중 가장 작은 것을 버려야 하기 때문입니다. 같은 값도 서로 다른 원소로 셉니다.

q = min(k, n)이라 하면 삽입·제거와 결과 추출을 합쳐 O(n log(q + 1)), 추가 공간 O(q)입니다. k가 n보다 크면 전체 값을 반환합니다. 숫자 범위가 작게 제한돼 있다면 빈도 배열이 더 나을 수도 있습니다.

## 숫자 외의 값에도 우선순위를 줄 수 있다

```js
const tasks = new BinaryHeap((a, b) => a.priority - b.priority || a.id - b.id);
tasks.push({ id: 2, priority: 1 });
tasks.push({ id: 1, priority: 1 });
tasks.push({ id: 3, priority: 0 });
console.log(tasks.pop());
```

priority가 작은 작업이 먼저, 같으면 id가 작은 작업이 먼저 나옵니다. 일반 힙은 같은 우선순위 원소의 입력 순서를 자동으로 보장하지 않습니다. FIFO가 필요하면 증가하는 순번을 비교 기준에 포함합니다.

힙에 들어간 객체의 priority를 밖에서 변경하면 힙 조건이 깨질 수 있습니다. 이 구현에는 특정 원소의 우선순위를 갱신하는 연산이 없습니다. 다음 편의 다익스트라에서는 기존 원소를 수정하는 대신 새 후보를 넣고, 오래된 후보를 꺼냈을 때 무시하는 방법을 쓰겠습니다.

## 확인할 경계

빈 힙에서 pop, 원소 하나를 넣고 pop, 중복 값, 감소 순서 삽입을 확인합니다. `(a, b) => b - a`를 주면 최대 힙으로 동작하는지도 봅니다. push와 pop을 번갈아 수행한 결과를 매번 정렬한 단순 모델과 비교하면 위로·아래로 이동하는 두 경로를 함께 검증할 수 있습니다.

힙을 배웠다고 모든 정렬 문제에 쓸 필요는 없습니다. 모든 값을 한 번에 정렬하면 되는 상황에서는 `sort()`가 더 간단합니다. **삽입과 우선 원소 추출이 섞이는가**를 기준으로 선택하겠습니다. 다음은 이 구조를 사용하는 [그래프 심화 편](/posts/algorithm-10-graph)입니다.
