링크를 슬랙이나 X에 붙이면 뜨는 미리보기 카드, 검색 결과에 나오는 제목과 설명 — 이 모두가 `<head>`의 메타 태그에서 옵니다. Next.js는 이 태그들을 **직접 쓰지 않고** 선언적으로 생성하게 해줍니다. 이 블로그도 그렇게 만들어졌죠.

메타데이터를 다루는 길은 셋입니다 — **정적 `metadata` 객체**, **동적 `generateMetadata` 함수**, 그리고 **파일 규칙**(OG 이미지·파비콘 등). 셋 다 서버 컴포넌트에서만 동작합니다.

## 정적 메타데이터

값이 고정이면 `layout.tsx`나 `page.tsx`에서 `metadata` 객체를 export합니다.

```tsx filename="app/layout.tsx"
import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "프론트엔드 기술 블로그",
  description: "직접 코드를 쓰며 정리하는 심화 프론트엔드 기록",
  openGraph: {
    title: "프론트엔드 기술 블로그",
    description: "…",
    type: "website",
  },
};
```

Next.js가 이 객체를 읽어 `<title>`, `<meta name="description">`, OG 태그를 자동으로 그려 넣습니다. 개발자 도구의 `<head>`에서 확인할 수 있죠.

## 제목 템플릿 — 반복 줄이기

블로그처럼 페이지마다 "글 제목 | 사이트명" 꼴이 필요하면 **템플릿**을 씁니다.

```tsx filename="app/layout.tsx"
export const metadata: Metadata = {
  title: {
    default: "프론트엔드 기술 블로그",       // 기본값
    template: "%s | 프론트엔드 기술 블로그", // 자식 페이지에 적용
  },
};
```

이제 각 글 페이지가 `title: "Next.js 캐싱"`만 지정하면 최종 제목은 "Next.js 캐싱 | 프론트엔드 기술 블로그"가 됩니다. (이 블로그 `layout.tsx`가 정확히 이 방식입니다.)

## 동적 메타데이터 — generateMetadata

제목·설명이 **데이터에 따라 달라지는** 경우(각 글마다 다른 제목)엔 `generateMetadata` 함수를 export합니다. 비동기이고, 라우트 파라미터를 받습니다.

```tsx filename="app/posts/[slug]/page.tsx"
import type { Metadata } from "next";

export async function generateMetadata({
  params,
}: {
  params: Promise<{ slug: string }>;
}): Promise<Metadata> {
  const { slug } = await params;   // params는 비동기 — await
  const post = await getPost(slug);

  return {
    title: post.title,
    description: post.description,
    openGraph: { title: post.title, type: "article" },
  };
}
```

여기서 부른 데이터(`getPost`)는 페이지 본문에서 다시 부르더라도 **요청 메모이제이션**으로 중복 요청되지 않습니다. ([데이터 패칭](/posts/nextjs-data-fetching)에서 다룬 그 최적화죠.)

## OG 이미지 — 파일 규칙으로

공유 카드의 **이미지**는 메타데이터 객체가 아니라 **파일 규칙**으로 만드는 게 깔끔합니다. 라우트 폴더에 `opengraph-image` 파일을 두면 됩니다.

- **정적**: `opengraph-image.png`를 폴더에 넣으면 끝.
- **동적**: `opengraph-image.tsx`에서 `ImageResponse`로 **코드로 이미지를 그립니다.**

```tsx filename="app/posts/[slug]/opengraph-image.tsx"
import { ImageResponse } from "next/og";

export const size = { width: 1200, height: 630 };
export const contentType = "image/png";

export default async function Image({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  const post = await getPost(slug);

  return new ImageResponse(
    (
      <div style={{ fontSize: 64, background: "#0a0a0a", color: "#fff", width: "100%", height: "100%", display: "flex", alignItems: "center", padding: 80 }}>
        {post.title}
      </div>
    ),
    size,
  );
}
```

JSX로 레이아웃을 짜면 Next.js가 그걸 **PNG로 렌더링**해 줍니다. 글마다 제목이 박힌 공유 이미지를 자동 생성할 수 있죠. (이 블로그도 `opengraph-image.tsx`로 카드를 만듭니다.)

## 파비콘·사이트맵·robots도 파일로

같은 파일 규칙으로 여러 메타 자산을 만듭니다.

- `icon.png` / `icon.svg` — 파비콘
- `sitemap.ts` — `MetadataRoute.Sitemap`을 반환해 사이트맵 자동 생성
- `robots.ts` — 크롤러 규칙

```ts filename="app/sitemap.ts"
import type { MetadataRoute } from "next";

export default function sitemap(): MetadataRoute.Sitemap {
  return getAllPosts().map((post) => ({
    url: `https://example.com/posts/${post.slug}`,
    lastModified: post.date,
  }));
}
```

## metadataBase — 절대 URL의 기준

OG 이미지 URL 등은 절대 경로여야 하는데, 매번 도메인을 쓰긴 번거롭습니다. `metadataBase`를 한 번 정하면 상대 경로를 알아서 절대 URL로 바꿔줍니다.

```tsx
export const metadata: Metadata = {
  metadataBase: new URL("https://myblog.com"),
};
```

---

Next.js 메타데이터의 철학은 "**head 태그를 손으로 쓰지 말고 선언하라**"입니다. 정적이면 객체로, 동적이면 `generateMetadata`로, 이미지·파비콘·사이트맵은 파일 규칙으로 — 각자 제자리가 있죠. [SEO 기초](/posts/seo-basics)에서 다룬 원칙이 프레임워크 기능으로 자연스럽게 녹아 있습니다. 이번 Next.js 묶음은 여기서 마무리합니다.
