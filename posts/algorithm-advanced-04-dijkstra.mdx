[미로 BFS](/posts/algorithm-05-dfs-bfs)에서는 한 번 이동할 때마다 비용이 1이었습니다. 이번에는 길마다 걸리는 시간이 다릅니다. **가장 적게 이동하는 길과 가장 빨리 도착하는 길이 달라질 수 있다**는 점부터 보겠습니다.

## 집에서 역까지 가는 두 가지 길

0번은 집, 1번은 편의점, 2번은 역입니다. 아래 길은 화살표 방향으로만 이동할 수 있다고 하겠습니다.

```text
집(0) ──5분──→ 역(2)
집(0) ──1분──→ 편의점(1) ──1분──→ 역(2)
```

역으로 바로 가면 5분, 편의점을 거치면 2분입니다. 이동 횟수는 바로 가는 길이 적지만, **시간은 편의점을 거치는 길이 더 짧습니다.** 우리가 구할 답은 각 장소까지 걸리는 최소 시간입니다.

## distance는 현재까지 찾은 최소 시간

처음에는 집까지 0분이라는 사실만 압니다. 아직 모르는 시간은 Infinity로 채웁니다.

```text
distance = [0, Infinity, Infinity]
            집   편의점      역
```

집에서 나가는 길을 보면 편의점은 1분, 역은 5분입니다. 이때 역의 5분은 **현재 아는 답**이고, 이후 더 빠른 길이 나오면 바꿀 수 있습니다.

## 가장 가까운 곳부터 확인한다

집을 확인한 다음에는 편의점 1분과 역 5분 중 더 가까운 편의점을 고릅니다. 편의점에서 역까지 가면 `1 + 1 = 2`분입니다. 현재 기록된 5분보다 짧으니 역의 답을 2로 바꿉니다.

| 확인한 장소 | 하는 계산 | 처리 후 distance |
| --- | --- | --- |
| 시작 전 | 집만 0 | `[0,∞,∞]` |
| 집 | 편의점 1, 역 5 기록 | `[0,1,5]` |
| 편의점 | 역의 5와 `1+1` 비교 | `[0,1,2]` |
| 역 | 더 갈 길 없음 | `[0,1,2]` |

이렇게 **아직 확인하지 않은 장소 중 거리가 가장 작은 곳을 골라 이웃의 답을 개선하는 방법**이 다익스트라입니다.

## visited는 거리가 확정됐다는 표시

`visited`는 단순히 발견한 장소가 아니라, 가장 가까운 장소로 선택해서 처리를 끝낸 곳에 붙입니다. 위 예제에서는 집 → 편의점 → 역 순서로 true가 됩니다.

역을 처음 발견한 순간에 확정하면 5분으로 답을 정해 버립니다. 편의점을 거쳐 2분으로 줄일 기회를 남겨야 하므로, **발견과 확정을 구분**합니다.

## 배열과 반복문으로 구현하기

`edges`의 각 항목은 `[출발, 도착, 시간]`입니다. 함수 안의 첫 반복문은 각 장소에서 나가는 길 목록을 만듭니다. 그다음 반복문은 가장 가까운 미확정 장소를 선택합니다.

```js
function dijkstra(n, edges, start) {
  const graph = Array.from({ length: n }, () => []);
  for (const [from, to, weight] of edges) {
    graph[from].push([to, weight]);
  }
  const distance = Array(n).fill(Infinity);
  const visited = Array(n).fill(false);
  distance[start] = 0;

  for (let step = 0; step < n; step++) {
    let node = -1;

    for (let i = 0; i < n; i++) {
      if (visited[i]) continue;
      if (node === -1 || distance[i] < distance[node]) {
        node = i;
      }
    }

    if (node === -1 || distance[node] === Infinity) break;
    visited[node] = true;

    for (const [next, weight] of graph[node]) {
      distance[next] = Math.min(distance[next], distance[node] + weight);
    }
  }
  return distance;
}


const edges = [
  [0, 1, 1],
  [0, 2, 5],
  [1, 2, 1],
];
console.log(dijkstra(3, edges, 0));
```

출력은 `[0,1,2]`입니다. 정점 번호와 시작점은 유효하고, 비용은 유한한 음수 아닌 수라고 가정합니다. 양쪽으로 갈 수 있는 길이면 반대 방향도 graph에 추가합니다.

## 코드에서 중요한 세 줄

| 코드 | 뜻 |
| --- | --- |
| `if (visited[i]) continue` | 이미 확정한 장소는 다시 고르지 않음 |
| `distance[i] < distance[node]` | 지금 후보보다 더 가까운 장소로 교체 |
| `Math.min(distance[next], distance[node] + weight)` | 기존 시간과 새로 찾은 시간을 비교 |

`node = -1`은 아직 장소를 고르지 않았다는 표시입니다. `node === -1`일 때는 첫 후보를 바로 선택합니다. 가장 가까운 미확정 거리도 Infinity라면 남은 장소에는 갈 수 없으므로 반복을 끝냅니다.

## 길의 비용이 음수면 안 되는 이유

이 방법은 한 번 가장 가까운 장소로 고른 뒤에는 다른 곳을 거쳐 더 짧아지지 않는다는 성질을 사용합니다. 남은 장소까지의 거리는 현재 거리 이상이고, 길을 더 가는 비용도 0 이상이기 때문입니다. 음수 길이 있으면 이 성질이 깨집니다.

정점 V개를 매번 훑어 고르므로 시간은 O(V² + E), 그래프와 두 배열을 포함한 공간은 O(V + E)입니다. E는 길의 개수입니다. 큰 그래프에서는 고르는 부분을 [최소 힙](/posts/algorithm-09-heap)으로 개선할 수 있지만, 먼저 이 세 장소의 거리 갱신을 이해하면 됩니다.
