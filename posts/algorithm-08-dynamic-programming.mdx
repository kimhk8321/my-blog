DP 문제에서 배열부터 선언하면 나중에 `dp[i]`가 무엇이었는지 헷갈립니다. 이번에는 코드 전에 상태를 한 문장으로 적겠습니다. **어떤 작은 문제의 답을 저장하는지**가 분명해야 초기값과 전이도 따라옵니다.

## 최소 동전 수의 상태

양의 정수 동전을 개수 제한 없이 사용해서 amount를 만듭니다. 최소 동전 수를 반환하고 만들 수 없으면 -1입니다. amount는 0 이상인 정수입니다.

`dp[x]`를 **금액 x를 정확히 만드는 최소 동전 수**라고 정합니다. 마지막으로 쓴 동전이 c라면 그전에는 x - c를 만들었어야 합니다.

```text
dp[0] = 0
dp[x] = min(dp[x - c] + 1), 단 c <= x이고 x - c가 도달 가능
```

0원을 만들 때는 아무것도 쓰지 않습니다. 아직 만들 수 없는 금액은 0이 아니라 `Infinity`로 둡니다.

```js
function minCoins(coins, amount) {
  const dp = Array(amount + 1).fill(Infinity);
  dp[0] = 0;

  for (let value = 1; value <= amount; value++) {
    for (const coin of coins) {
      if (coin <= value) {
        dp[value] = Math.min(dp[value], dp[value - coin] + 1);
      }
    }
  }
  return dp[amount] === Infinity ? -1 : dp[amount];
}

console.log(minCoins([1, 3, 4], 6));
console.log(minCoins([2], 3));
console.log(minCoins([], 0));
```

결과는 `2`, `-1`, `0`입니다. [그리디 편](/posts/algorithm-07-greedy)에서 틀린 `[1, 3, 4]`도 모든 마지막 동전 후보를 비교하니 해결됩니다.

동전 종류 수가 m, 금액이 A라면 시간 O(A × m), 공간 O(A)입니다. A가 매우 크면 이 풀이도 쓸 수 없습니다. 입력에 쓰인 비트 수에 대한 다항 시간이 아니라 **금액 수치 자체**에 비례하는 의사 다항 시간이라는 점도 구분합니다.

## 왜 이전 답만으로 충분한가

금액 x에 도달한 경로가 다르더라도 이후 선택할 수 있는 동전 집합은 같습니다. 따라서 x를 더 많은 동전으로 만든 경로는 남길 이유가 없습니다. 같은 상태에서는 가장 적은 동전 수만 기억해도 앞으로의 최적 선택을 잃지 않습니다.

하지만 동전마다 남은 수가 다르면 금액만으로는 상태가 부족합니다. 같은 x여도 남은 동전이 다르면 미래 선택이 달라집니다. **같은 상태로 합쳐도 이후의 선택 조건이 같은가?**가 상태 설계의 기준입니다.

재귀로 풀면서 같은 금액을 반복 계산한다면 메모이제이션을 붙일 수 있습니다. 다만 JavaScript에서는 목표 금액이 커질 때 재귀 깊이도 문제가 되므로 이 예제는 작은 금액부터 채웠습니다.

## 0/1 배낭은 각 물건을 한 번만

물건은 `{ weight, value }` 형태이고 무게는 양의 정수입니다. 용량 이하에서 얻을 수 있는 최대 가치를 구합니다. 물건을 고르지 않아도 되며 같은 물건은 한 번만 사용할 수 있습니다.

이차원 상태라면 `dp[i][capacity]`는 앞의 i개 물건만 사용한 최대 가치입니다. 현재 물건을 고르지 않거나, 고른 뒤 이전 행에서 남은 용량의 답을 가져옵니다.

이전 행 전체를 저장하지 않고 일차원으로 줄일 때 순회 방향이 중요해집니다.

```js
function knapsack01(items, capacity) {
  const dp = Array(capacity + 1).fill(0);

  for (const { weight, value } of items) {
    for (let space = capacity; space >= weight; space--) {
      dp[space] = Math.max(dp[space], dp[space - weight] + value);
    }
  }
  return dp[capacity];
}

console.log(knapsack01([{ weight: 2, value: 3 }], 4));
console.log(knapsack01([
  { weight: 2, value: 3 },
  { weight: 3, value: 4 },
  { weight: 4, value: 5 },
], 5));
```

결과는 3과 7입니다. 공간을 큰 쪽부터 순회해야 `dp[space - weight]`에 **현재 물건을 아직 반영하지 않은 이전 행의 값**이 남습니다.

오름차순으로 돌면 무게 2인 물건 하나로 `dp[2] = 3`을 만든 뒤, 바로 그 값을 사용해 `dp[4] = 6`을 만듭니다. 같은 물건을 두 번 사용한 셈입니다. 공간 압축은 저장량만 바꾸는 작업이 아니라 읽는 값의 의미까지 바꿀 수 있습니다.

물건 수 n, 용량 W에 대해 시간 O(nW), 공간 O(W)입니다. 여기서는 “정확히 W를 채우기”가 아니라 “W 이하에서 최대 가치”라 초기값이 전부 0이어도 됩니다. 정확히 채우는 문제라면 0 용량 외에는 도달 불가능 상태를 따로 둬야 합니다.

## 점화식이 맞아도 개수 문제는 또 다르다

동전으로 만드는 방법의 수를 셀 때는 `1 + 2`와 `2 + 1`을 같은 답으로 보는지가 중요합니다. 금액을 바깥에서 순회하는지, 동전을 바깥에서 순회하는지에 따라 순서를 센 결과와 조합을 센 결과가 달라질 수 있습니다. 최소값 문제의 반복문을 그대로 복사하지 말고 무엇을 세는지 다시 정의해야 합니다.

DP를 복습할 때는 상태의 뜻, 초기값, 전이, 계산 순서, 최종 답 위치를 차례대로 적습니다. 이 다섯 가지 중 하나라도 설명하기 어렵다면 배열 인덱스를 더 붙이기 전에 문제 조건으로 돌아가겠습니다. [DP의 메모이제이션·바텀업 설명](https://cp-algorithms.com/dynamic_programming/intro-to-dp.html)도 참고했습니다.
