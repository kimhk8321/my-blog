오랜만에 알고리즘을 공부하면 개념보다 “이걸 JS로 어떻게 썼더라?”에서 막힐 때가 있습니다. 이번 시리즈는 자주 쓰는 문법을 먼저 보고, 작은 대표 예제를 직접 따라가는 방식으로 정리합니다.

첫 주제는 해시입니다. **이름으로 개수를 찾거나, 어떤 값이 이미 나왔는지 확인할 때** 떠올리면 됩니다. JS에서는 보통 `Map`과 `Set`을 사용합니다. 이 시리즈의 숫자 예제는 계산 결과까지 안전한 정수 범위 안에 있다고 가정합니다.

## 자주 쓰는 Map 문법

`Map`은 키와 값을 묶어 저장합니다. 이름을 키로, 등장 횟수를 값으로 두면 이름별 개수를 셀 수 있습니다.

```js
const counts = new Map();

counts.set("kim", 2);
counts.set("lee", 1);

console.log(counts.get("kim"));
console.log(counts.has("park"));
console.log(counts.size);

counts.delete("lee");
console.log([...counts]);
```

결과는 순서대로 `2`, `false`, `2`, `[["kim", 2]]`입니다. `size`는 값의 합이 아니라 **서로 다른 키의 수**입니다. 존재하지 않는 키를 `get()`하면 `undefined`를 반환합니다.

| 문법 | 역할 |
| --- | --- |
| `map.set(key, value)` | 저장하거나 기존 값을 변경 |
| `map.get(key)` | 값 읽기 |
| `map.has(key)` | 키가 있는지 확인 |
| `map.delete(key)` | 항목 삭제 |
| `for (const [key, value] of map)` | 키와 값을 하나씩 읽기 |

## 이름별 개수 세기

```js
function countNames(names) {
  const result = new Map();

  for (const name of names) {
    const previous = result.get(name) ?? 0;
    result.set(name, previous + 1);
  }
  return result;
}

console.log([...countNames(["kim", "lee", "kim"])]);
```

결과는 `[["kim", 2], ["lee", 1]]`입니다. `?? 0`은 아직 저장하지 않은 이름을 0회로 취급하기 위해 씁니다.

```text
kim 처리 → { kim: 1 }
lee 처리 → { kim: 1, lee: 1 }
kim 처리 → { kim: 2, lee: 1 }
```

위 표기는 Map을 읽기 쉽게 적은 것입니다. 실제로 `map[name]`을 쓰는 것이 아니라 `get()`과 `set()`으로 접근합니다.

## 대표 예제: 완주하지 못한 사람 찾기

참가자 중 한 사람만 완주하지 못했습니다. 동명이인이 있을 수 있습니다. 참가자의 이름별 개수를 올린 뒤, 완주한 사람의 개수를 하나씩 내리면 됩니다.

```js
function findNonCompleter(participants, completed) {
  const remaining = countNames(participants);

  for (const name of completed) {
    remaining.set(name, remaining.get(name) - 1);
  }

  for (const [name, count] of remaining) {
    if (count > 0) return name;
  }
  return null;
}

console.log(findNonCompleter(
  ["kim", "lee", "kim", "park"],
  ["lee", "park", "kim"],
));
```

답은 `"kim"`입니다. 앞의 `countNames()`와 함께 실행하면 됩니다. 문제 조건은 완주자 목록이 참가자 목록에 포함되고, 정확히 한 사람이 빠진 경우입니다.

```text
참가자 집계     { kim: 2, lee: 1, park: 1 }
lee 완주 처리   { kim: 2, lee: 0, park: 1 }
park 완주 처리  { kim: 2, lee: 0, park: 0 }
kim 완주 처리   { kim: 1, lee: 0, park: 0 }
```

이름마다 배열을 다시 찾는 대신 개수를 바로 읽습니다. 일반적인 해시 구현의 평균 조회 비용을 O(1)로 가정하면 시간 O(n), 공간 O(n)입니다. JS 명세가 모든 Map 조회에 O(1)을 보장하는 것은 아니며, 이 분석은 코딩테스트에서 흔히 사용하는 가정입니다. [MDN Map](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Map)을 참고했습니다.

## 중복만 없애면 될 때는 Set

```js
const unique = new Set([1, 2, 2, 3, 1]);
console.log(unique.size);
console.log(unique.has(2));
console.log([...unique]);
```

결과는 `3`, `true`, `[1, 2, 3]`입니다. Set은 같은 값을 한 번만 저장하므로 **종류 수**를 구할 때 편합니다. 동명이인이 몇 명인지 알아야 하는 미완주자 문제에는 Set만으로 부족합니다.
