반응형 웹은 오랫동안 **미디어 쿼리**로 만들었습니다. `@media (min-width: 768px)` — "화면이 768px 이상이면." 그런데 컴포넌트 시대에 이건 근본적인 한계가 있습니다. 같은 카드 컴포넌트라도 **넓은 메인 영역**에 놓일 때와 **좁은 사이드바**에 놓일 때 다르게 보여야 하는데, 미디어 쿼리는 오직 **화면 전체 크기**만 알 뿐 그 카드가 지금 얼마나 좁은 곳에 있는지는 모릅니다.

**컨테이너 쿼리(Container Queries)** 가 이 간극을 메웁니다. 화면이 아니라 **부모 컨테이너의 크기**에 반응하죠. 컴포넌트가 자기가 놓인 공간을 보고 스스로 레이아웃을 정합니다.

## 미디어 쿼리 vs 컨테이너 쿼리

```css
/* 미디어 쿼리: 화면(viewport) 기준 */
@media (min-width: 768px) { .card { flex-direction: row; } }

/* 컨테이너 쿼리: 부모 컨테이너 기준 */
@container (min-width: 380px) { .card { flex-direction: row; } }
```

문법은 거의 같지만 의미가 다릅니다. 미디어 쿼리 카드는 "화면이 넓으면" 가로가 되고, 컨테이너 쿼리 카드는 "**내가 놓인 자리가** 넓으면" 가로가 됩니다. 후자는 사이드바에 넣으면 알아서 세로, 메인에 넣으면 알아서 가로가 되죠. **컴포넌트를 어디든 재사용**할 수 있게 됩니다.

## 두 줄이면 된다

컨테이너 쿼리를 쓰려면 두 가지만 하면 됩니다.

**① 부모를 "컨테이너"로 선언** — `container-type`을 줍니다.

```css
.wrapper {
  container-type: inline-size; /* 가로 크기를 쿼리 기준으로 */
}
```

`inline-size`는 "가로 크기만 본다"는 뜻으로, 가장 흔하고 안전한 선택입니다(세로까지 보는 `size`는 높이가 내용에 의존해 순환 참조가 나기 쉬움).

**② 자식에서 `@container`로 조건 스타일** — 가장 가까운 컨테이너 조상을 기준으로 반응합니다.

```css
.card { display: flex; flex-direction: column; }

@container (min-width: 380px) {
  .card { flex-direction: row; }
}
```

이게 전부입니다. `.card`는 `.wrapper`의 실제 폭에 따라 배치를 바꿉니다.

## 이름 붙은 컨테이너

컨테이너가 중첩되면 "어느 컨테이너를 기준으로 할지" 헷갈립니다. 이름을 붙여 특정 컨테이너를 콕 집을 수 있습니다.

```css
.sidebar { container: layout / inline-size; } /* 이름: layout */

@container layout (min-width: 300px) {
  .widget { ... } /* 반드시 layout 컨테이너 기준 */
}
```

## 컨테이너 쿼리 단위 — cqw, cqi

미디어 쿼리에 `vw`가 있다면, 컨테이너 쿼리엔 `cqw`(컨테이너 폭의 1%), `cqi`(inline 크기의 1%)가 있습니다. 컨테이너 크기에 비례하는 타이포그래피·여백을 만들 때 유용합니다.

```css
.title {
  font-size: clamp(1rem, 5cqi, 2rem); /* 컨테이너가 넓어질수록 제목도 커짐 */
}
```

## Tailwind에서

Tailwind CSS는 컨테이너 쿼리를 내장 지원합니다. 부모에 `@container`, 자식에 `@md:`·`@lg:` 같은 변형을 씁니다(뷰포트 기준 `md:`와 구분).

```html
<div class="@container">
  <div class="flex flex-col @md:flex-row">…</div>
</div>
```

## 언제 쓰나

- **디자인 시스템·재사용 카드**: 여러 폭의 슬롯에 들어가는 컴포넌트라면 컨테이너 쿼리가 정답입니다.
- **대시보드 위젯**: 그리드 칸 크기에 따라 위젯이 알아서 요약형/상세형으로.
- 반대로 **페이지 전체 레이아웃**(헤더·사이드바 접기 등)은 여전히 미디어 쿼리가 자연스럽습니다.

이제 모든 최신 브라우저가 컨테이너 쿼리를 지원하니, "이 컴포넌트는 화면이 아니라 자기 공간에 반응해야 한다" 싶을 때 주저 없이 쓰면 됩니다.

---

컨테이너 쿼리는 반응형의 사고를 **"화면 기준"에서 "컴포넌트 기준"으로** 옮깁니다. 컴포넌트가 자신이 놓인 맥락을 스스로 읽고 적응하니, 진정한 의미의 재사용 가능한 반응형 UI가 완성되죠. 오늘 7편은 여기서 마무리합니다.
