관리자 A와 B가 같은 글을 열었습니다. A가 제목을 수정해 저장하고, 조금 뒤 B가 본문을 고쳐 저장했습니다. 서버가 받은 값을 그대로 덮어쓰면 B의 화면에 남아 있던 옛 제목이 함께 저장돼 **A의 수정이 아무 경고 없이 사라집니다.**

이것이 Lost Update입니다. 마지막 저장이 이기는 방식은 단순하지만, 먼저 저장한 사람의 작업을 조용히 버립니다.

A와 B의 내용을 각각 바꾼 뒤 차례로 저장해 보세요. 먼저 저장한 편집기가 서버 버전을 올립니다. 뒤늦게 저장한 편집기는 자신이 읽은 버전과 서버 버전이 달라 `409 Conflict`를 받습니다.

## version을 함께 읽고 보낸다

```ts
type Article = {
  id: string;
  title: string;
  body: string;
  version: number;
};
```

클라이언트는 데이터를 읽을 때 받은 `version`을 수정 요청에도 보냅니다.

```http
PATCH /api/articles/42
Content-Type: application/json

{
  "title": "수정한 제목",
  "version": 7
}
```

서버는 현재 버전이 7일 때만 수정하고 동시에 8로 올립니다.

```sql
UPDATE articles
SET title = ?, version = version + 1
WHERE id = ? AND version = ?;
```

영향받은 행이 1개면 성공, 0개면 그사이 누군가 바꾼 것입니다. 조회와 수정이 한 SQL 문에 있으므로 두 요청이 동시에 들어와도 하나만 조건을 통과합니다.

```ts
if (result.affectedRows === 0) {
  return Response.json(
    { code: "VERSION_CONFLICT", current: await findArticle(id) },
    { status: 409 },
  );
}
```

## ETag와 If-Match

HTTP의 조건부 요청으로 같은 뜻을 표현할 수도 있습니다. 서버가 조회 응답에 `ETag: "article-42-v7"`을 보내고, 클라이언트가 수정 요청의 `If-Match`에 그 값을 담습니다. 현재 ETag가 다르면 서버는 `412 Precondition Failed`를 반환합니다.

REST의 조건부 요청을 따르려면 ETag가 자연스럽고, 사내 API에서 명시적인 도메인 버전을 쓰려면 body의 `version`과 409도 이해하기 쉽습니다. 핵심은 **내가 읽은 상태가 아직 최신인지 조건부로 저장하는 것**입니다.

## 충돌을 UI에서 푸는 법

충돌을 감지하는 것만으로 사용자의 작업이 보존되지는 않습니다. 응답에 최신 서버 값을 포함하고 UI는 선택지를 줘야 합니다.

- 최신 내용을 불러오고 내 변경을 다시 적용한다.
- 필드별 차이를 보여 주고 사용자가 합친다.
- 자동 병합이 안전한 필드만 합친다.
- 권한이 있다면 덮어쓰되 그 사실을 분명히 알린다.

짧은 프로필 폼은 최신 값을 보여주고 다시 수정하게 해도 충분합니다. 긴 문서는 내 초안을 따로 보존하고 diff를 제공해야 합니다.

## 낙관적 업데이트와는 다르다

[React의 낙관적 업데이트](/posts/optimistic-updates)는 서버가 성공할 것이라 보고 UI를 먼저 바꾸는 UX 전략입니다. 낙관적 동시성 제어는 충돌이 드물 것이라 보고 락 없이 진행하다 **저장 시점에 버전을 검증하는 데이터 전략**입니다.

| 구분 | 낙관적 업데이트 | 낙관적 동시성 제어 |
| --- | --- | --- |
| 목적 | 응답 전 UI 반영 | Lost Update 방지 |
| 실패 조건 | 서버 요청 실패 | 읽은 뒤 데이터가 변경됨 |
| 대응 | UI 롤백 | 새 버전과 병합 후 재시도 |

충돌이 드물고 사용자가 오래 편집하는 문서에는 낙관적 방식이 잘 맞습니다. 반대로 짧은 트랜잭션에서 충돌이 잦고 재시도 비용이 크면 비관적 락을 검토할 수 있습니다.

---

마지막 저장 승리는 충돌을 해결한 게 아니라 한쪽 변경을 버린 것입니다. `version` 또는 `ETag`를 조건으로 저장하면 서버는 충돌을 놓치지 않고, UI는 사용자의 작업을 살려 병합할 기회를 얻습니다.
