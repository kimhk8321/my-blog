"느린 것 같아서 `memo`를 붙였다"는 최적화는 대개 효과가 없거나, 오히려 코드만 복잡하게 만듭니다. 성능 작업의 첫걸음은 코드를 고치는 게 아니라 **측정하는 것**입니다. 무엇이, 얼마나 자주, 왜 다시 그려지는지부터 봐야 합니다.

## 리렌더는 언제 일어나는가

React 컴포넌트가 다시 렌더되는 이유는 셋뿐입니다.

1. 자신의 **state**가 바뀌었다.
2. 구독 중인 **context** 값이 바뀌었다.
3. **부모가 리렌더**됐다 (props가 그대로여도).

사람들이 가장 자주 놓치는 게 3번입니다. 부모가 렌더되면 자식은 props가 똑같아도 기본적으로 따라 렌더됩니다.

<RerenderCountDemo />

버튼을 누르면 부모만 바뀌는데도 "일반 자식"의 렌더 횟수가 계속 오릅니다. `React.memo`로 감싼 자식은 props가 그대로라 멈춰 있죠. 이 차이가 최적화의 출발점입니다.

## 감이 아니라 Profiler로

React DevTools의 **Profiler** 탭이 사실상의 표준 도구입니다.

1. Profiler 탭 → 녹화 버튼을 누르고
2. 느리다고 느낀 상호작용을 한 번 하고
3. 녹화를 멈춥니다.

그러면 커밋마다 어떤 컴포넌트가 얼마나 걸렸는지 **불꽃 그래프(flamegraph)** 로 보여줍니다. 노란색·주황색으로 넓게 칠해진 컴포넌트가 시간을 잡아먹는 범인입니다. "Highlight updates when components render" 옵션을 켜면 리렌더되는 컴포넌트가 화면에서 번쩍여, 예상 못 한 렌더를 눈으로 잡을 수 있습니다.

핵심 원칙: **넓고 자주 렌더되는 것부터** 잡습니다. 어쩌다 한 번 도는 컴포넌트를 `memo`로 감싸봐야 얻는 게 없습니다.

## memo — 부모 리렌더를 차단

`React.memo`는 props가 이전과 얕게 같으면 렌더를 건너뜁니다. 위 데모의 "React.memo 자식"이 그래서 멈춰 있었죠.

```jsx
const Row = memo(function Row({ item }) {
  return <li>{item.name}</li>;
});
```

주의: `memo`는 props를 **얕게(shallow)** 비교합니다. 그래서 매 렌더마다 새로 만들어지는 객체·배열·함수를 props로 넘기면 아무 소용이 없습니다.

```jsx
// 이러면 memo가 무력화됨 — style이 매번 새 객체
<Row item={item} style={{ margin: 8 }} />
```

## useMemo / useCallback — 참조를 안정시키기

그래서 `memo`와 짝을 이루는 게 이 둘입니다. **"자식에게 넘기는 값의 참조를 고정"** 하는 도구죠.

```jsx
function List({ items, query }) {
  // 값: query가 바뀔 때만 다시 계산
  const filtered = useMemo(
    () => items.filter((i) => i.name.includes(query)),
    [items, query],
  );

  // 함수: 참조를 고정해 memo된 자식이 헛돌지 않게
  const onSelect = useCallback((id) => {
    console.log("selected", id);
  }, []);

  return filtered.map((i) => (
    <Row key={i.id} item={i} onSelect={onSelect} />
  ));
}
```

`useMemo`는 **비싼 계산**이나 **참조 안정성**이 필요할 때, `useCallback`은 **함수를 memo된 자식에게 넘길 때** 씁니다. 반대로 말하면, memo된 자식에게 넘기지도 않는 함수를 `useCallback`으로 감싸는 건 이득 없는 복잡도입니다.

## 그 전에, 공짜 최적화들

memo를 꺼내기 전에 값싸게 먹히는 방법이 있습니다.

- **state를 필요한 곳까지 내리기.** 입력값 state를 페이지 최상단이 아니라 입력 컴포넌트 안에 두면, 타이핑할 때 페이지 전체가 아니라 그 컴포넌트만 렌더됩니다.
- **children으로 넘기기.** 자주 바뀌는 컴포넌트가 무거운 자식을 `props.children`으로 받으면, 부모가 렌더돼도 그 children은 참조가 유지돼 다시 렌더되지 않습니다.

```jsx
// Wrapper가 아무리 자주 렌더돼도 <Heavy />는 재렌더 안 됨
<Wrapper>
  <Heavy />
</Wrapper>
```

구조만 바꿔도 해결되는 경우가 생각보다 많습니다. `memo`는 그걸로 안 될 때 꺼내는 카드입니다.

## React Compiler는?

React 19와 함께 나온 **React Compiler**는 이 memoization을 컴파일 타임에 자동으로 넣어줍니다. 도입하면 위의 `useMemo`/`useCallback` 상당수를 손으로 쓸 필요가 없어지죠. 다만 자동화가 있어도 "무엇이 왜 리렌더되는가"를 읽는 눈은 여전히 필요합니다. 컴파일러도 못 잡는 구조적 문제(state 위치, context 설계)는 결국 사람이 판단해야 하니까요.
