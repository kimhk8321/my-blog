그래프라는 단어만으로는 풀이를 고를 수 없습니다. “가장 싸게 이동하기”, “먼저 해야 할 작업 순서”, “두 점이 같은 덩어리인지”는 다른 질문입니다. 마지막 편에서는 질문을 나눠 보겠습니다.

| 필요한 답 | 먼저 검토할 알고리즘 |
| --- | --- |
| 같은 비용의 간선에서 최소 이동 수 | BFS |
| 음수 없는 가중치에서 한 시작점의 최단 거리 | 다익스트라 |
| 방향 그래프의 선행 조건을 지키는 순서 | 위상 정렬 |
| 간선을 추가하며 연결 여부 확인 | Union-Find |
| 모든 정점을 최소 총비용으로 연결 | 크루스칼 또는 프림 |

모든 코드의 정점 번호는 0부터 n - 1까지입니다. 가중치와 거리 합은 안전한 정수 범위 안에 있다고 가정합니다.

## 다익스트라: 지금까지 가장 가까운 후보부터

BFS는 먼저 발견한 경로가 최단이지만 가중치가 다르면 그렇지 않습니다. `0 → 1`이 10이고 `0 → 2 → 1`이 각각 1, 1이라면 직접 가는 한 간선이 더 비쌉니다.

최소 힙에서 가장 작은 거리 후보를 꺼내고 더 짧은 경로가 발견되면 이웃을 갱신합니다. 아래 코드는 **[9편의 BinaryHeap](/posts/algorithm-09-heap)을 같은 실행 환경에 선언한 뒤** 실행합니다. 간선은 `[출발, 도착, 비용]` 형태의 방향 간선이며 비용은 0 이상입니다.

```js
function dijkstra(n, edges, start) {
  const graph = Array.from({ length: n }, () => []);
  for (const [from, to, weight] of edges) graph[from].push([to, weight]);
  const distance = Array(n).fill(Infinity);
  const heap = new BinaryHeap((a, b) => a[0] - b[0]);
  distance[start] = 0;
  heap.push([0, start]);

  while (heap.size > 0) {
    const [cost, node] = heap.pop();
    if (cost !== distance[node]) continue;
    for (const [next, weight] of graph[node]) {
      const candidate = cost + weight;
      if (candidate >= distance[next]) continue;
      distance[next] = candidate;
      heap.push([candidate, next]);
    }
  }
  return distance;
}

console.log(dijkstra(4, [[0, 1, 10], [0, 2, 1], [2, 1, 1]], 0));
```

결과는 `[0, 2, 1, Infinity]`입니다. 3번 정점은 연결되지 않았습니다. 무방향 그래프라면 양방향 간선을 넣어야 합니다.

1번 정점은 거리 10 후보가 먼저 들어갔어도, 거리 2로 갱신될 수 있습니다. 나중에 10 후보가 나오면 현재 거리와 다르므로 건너뜁니다. 이 검사를 빼면 오래된 후보로 이웃을 다시 훑으며 시간이 크게 늘어날 수 있습니다. [희소 그래프 다익스트라 설명](https://cp-algorithms.com/graph/dijkstra_sparse.html)에서도 이런 오래된 후보 제거를 다룹니다.

음수 간선이 없으므로 가장 작은 유효 후보를 꺼냈을 때 나중에 더 짧은 우회 경로가 생기지 않습니다. 음수 간선에는 이 근거가 무너지며, 음수 사이클이 있으면 위 코드도 종료를 보장할 수 없습니다. 벨만–포드 같은 별도 방법이 필요합니다.

이 구현은 decrease-key 없이 중복 후보를 허용합니다. 간선 수 E만큼 후보가 생길 수 있어 보수적으로 O(V + E + (E + 1) log(E + 2)) 시간, 그래프와 힙에 O(V + E) 공간입니다. 단순 그래프에서는 흔히 O((V + E) log V)로 정리합니다.

## 위상 정렬: 진입 차수가 0인 작업부터

의존성 `[a, b]`는 a를 끝낸 뒤 b를 할 수 있다는 뜻입니다. 현재 들어오는 간선이 없는 정점부터 처리하고, 그 정점에서 나가는 간선을 제거합니다.

```js
function topologicalOrder(n, edges) {
  const graph = Array.from({ length: n }, () => []);
  const indegree = Array(n).fill(0);
  for (const [from, to] of edges) {
    graph[from].push(to);
    indegree[to]++;
  }

  const queue = [];
  for (let node = 0; node < n; node++) {
    if (indegree[node] === 0) queue.push(node);
  }
  let head = 0;
  const order = [];
  while (head < queue.length) {
    const node = queue[head++];
    order.push(node);
    for (const next of graph[node]) {
      if (--indegree[next] === 0) queue.push(next);
    }
  }
  return order.length === n ? order : null;
}

console.log(topologicalOrder(4, [[0, 2], [1, 2], [2, 3]]));
console.log(topologicalOrder(2, [[0, 1], [1, 0]]));
```

첫 결과는 `[0, 1, 2, 3]`, 두 번째는 `null`입니다. 모든 정점을 처리하지 못했다면 순환 의존성이 남아 있습니다. 위상 순서는 여러 개일 수 있으므로 특정 배열 하나와만 비교하기보다 **모든 간선에서 출발 정점이 먼저 나오는지** 검증해야 합니다.

시간과 공간은 O(V + E)입니다. 가능한 작업 중 번호가 가장 작은 것을 항상 골라야 한다면 FIFO 큐 대신 최소 힙을 써야 하고 복잡도도 달라집니다. 위상 정렬은 방향 비순환 그래프의 순서 문제이며, 무방향 그래프의 정렬에 그대로 쓰는 개념은 아닙니다. [위상 정렬의 정의와 사이클 조건](https://cp-algorithms.com/graph/topological-sort.html)도 함께 확인했습니다.

## Union-Find: 같은 집합인지 확인하기

서로소 집합은 각 정점의 대표를 추적합니다. find는 대표를 찾고 union은 서로 다른 두 집합을 합칩니다. 경로 압축과 크기 기준 합치기를 함께 씁니다.

```js
class DisjointSet {
  constructor(n) {
    this.parent = Array.from({ length: n }, (_, i) => i);
    this.sizes = Array(n).fill(1);
  }
  find(node) {
    while (this.parent[node] !== node) {
      this.parent[node] = this.parent[this.parent[node]];
      node = this.parent[node];
    }
    return node;
  }
  union(a, b) {
    let rootA = this.find(a);
    let rootB = this.find(b);
    if (rootA === rootB) return false;
    if (this.sizes[rootA] < this.sizes[rootB]) [rootA, rootB] = [rootB, rootA];
    this.parent[rootB] = rootA;
    this.sizes[rootA] += this.sizes[rootB];
    return true;
  }
}

const groups = new DisjointSet(4);
groups.union(0, 1);
groups.union(1, 2);
console.log(groups.find(0) === groups.find(2));
console.log(groups.find(0) === groups.find(3));
```

결과는 true, false입니다. 연산을 여러 번 수행했을 때 분할 상환 O(α(V))이며 α는 역 아커만 함수라 실용적인 크기에서 매우 작습니다. 정확한 O(1)이라고 단정하지는 않습니다. 공간은 O(V)입니다.

기본 Union-Find는 간선 추가와 합치기에 적합합니다. 간선을 삭제하며 집합을 다시 분리하는 기능은 없고, 방향 그래프의 도달 가능성도 이 구조만으로 알 수 없습니다. 최적화와 분할 상환 분석은 [서로소 집합 설명](https://cp-algorithms.com/data_structures/disjoint_set_union.html)을 참고했습니다.

## 크루스칼: 사이클을 만들지 않는 싼 간선

무방향 가중 그래프에서 모든 정점을 연결하는 최소 신장 트리의 총비용을 구합니다. 간선을 싼 순서대로 보며 서로 다른 집합만 연결합니다. 연결할 수 없으면 `null`입니다. 앞의 DisjointSet 선언과 함께 실행합니다.

```js
function minimumSpanningCost(n, edges) {
  if (n <= 1) return 0;
  const groups = new DisjointSet(n);
  const sorted = [...edges].sort((a, b) => a[2] - b[2]);
  let count = 0;
  let total = 0;
  for (const [a, b, weight] of sorted) {
    if (!groups.union(a, b)) continue;
    total += weight;
    if (++count === n - 1) return total;
  }
  return null;
}

console.log(minimumSpanningCost(3, [[0, 1, 5], [1, 2, 2], [0, 2, 1]]));
```

답은 3입니다. 정렬을 O(E log E)로 가정하면 초기화와 집합 연산까지 O(V + E log(E + 1) + Eα(V)) 시간, 복사한 간선과 집합에 O(V + E) 공간입니다. 다익스트라와 달리 최소 신장 트리는 음수 간선도 허용합니다.

선택한 집합을 가르는 간선 중 가장 싼 것을 더해도 되는 컷 성질이 근거입니다. 최단 경로 트리와 최소 신장 트리는 목표가 다릅니다. 모든 정점까지의 거리가 짧다고 전체 연결 비용도 최소가 되는 것은 아닙니다. [크루스칼의 정확성 설명](https://cp-algorithms.com/graph/mst_kruskal.html)에서도 간선을 교환하는 방식으로 이 선택을 설명합니다.
