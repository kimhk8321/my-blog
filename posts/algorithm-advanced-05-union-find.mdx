세 사람의 번호가 0, 1, 2이고 처음에는 각자 다른 팀이라고 하겠습니다. 0과 1이 팀을 만들고, 나중에 2도 그 팀에 들어옵니다. **두 사람이 같은 팀인지 확인하고, 두 팀을 합치는 작업**을 반복하는 문제입니다.

[기초 그래프 글](/posts/algorithm-10-graph)에서는 연결을 따라 DFS로 그룹을 찾았습니다. Union-Find는 매번 전체 연결을 훑는 대신 **각 팀의 대표자가 누구인지** 기록합니다.

## parent 배열은 누구를 따라가야 하는지 적는다

처음에는 모두 자기 자신이 대표자입니다.

```text
사람 번호:  0  1  2
parent:   [0, 1, 2]
```

0과 1을 합칠 때 0을 대표자로 정하면 `parent[1] = 0`으로 바꿉니다.

```text
parent = [0, 0, 2]
0은 0을 가리킴 → 0이 대표자
1은 0을 가리킴 → 1도 대표자가 0
2는 2를 가리킴 → 아직 다른 팀
```

대표자는 반드시 가장 작은 번호일 필요는 없습니다. 같은 팀 사람들이 같은 대표자를 찾을 수 있으면 됩니다.

## find는 대표자를 찾는 함수

어떤 사람의 parent가 자기 자신이 아니라면 그 부모를 따라갑니다. 자기 자신을 가리키는 사람에 도착하면 대표자를 찾은 것입니다.

```js
function find(parent, x) {
  while (x !== parent[x]) {
    parent[x] = parent[parent[x]];
    x = parent[x];
  }
  return x;
}
```

`parent[x] = parent[parent[x]]`는 x가 부모보다 한 단계 위를 가리키게 합니다. 대표자를 찾으면서 경로도 줄이는 **path halving** 방식입니다. 읽기만 하는 함수는 아니고 parent도 바뀝니다.

처음에는 다음 계산만 확인해도 충분합니다.

```text
parent = [0,0,2]
find(parent, 0) → 0
find(parent, 1) → 0
find(parent, 2) → 2
```

0과 1의 결과가 같으니 같은 팀입니다. 0과 2는 결과가 다르므로 다른 팀입니다.

## union은 두 팀의 대표자를 연결한다

사람 한 명을 옮기는 대신 **두 대표자를 연결**해야 팀 전체가 합쳐집니다. `size`에는 대표자가 관리하는 팀의 인원수를 저장합니다. 작은 팀을 큰 팀 아래 붙이면 부모를 따라갈 경로가 불필요하게 길어지는 것을 줄일 수 있습니다.

```js
function union(parent, size, a, b) {
  let rootA = find(parent, a);
  let rootB = find(parent, b);
  if (rootA === rootB) return false;
  if (size[rootA] < size[rootB]) [rootA, rootB] = [rootB, rootA];
  parent[rootB] = rootA;
  size[rootA] += size[rootB];
  return true;
}
```

`rootA`, `rootB`는 각각 두 사람의 대표자입니다. 이미 같으면 아무 일도 하지 않고 false를 반환합니다. 다르면 작은 팀의 대표자를 큰 팀에 붙이고 true를 반환합니다.

`[rootA, rootB] = [rootB, rootA]`는 두 변수의 값을 바꿉니다. 이 줄을 거치면 rootA가 더 크거나 같은 팀의 대표자가 됩니다.

## 세 사람으로 실행하기

```js
const n = 3;
const parent = Array.from({ length: n }, (_, i) => i);
const size = Array(n).fill(1);
let groups = n;

if (union(parent, size, 0, 1)) groups--;
console.log(find(parent, 0) === find(parent, 1));
console.log(find(parent, 0) === find(parent, 2));

if (union(parent, size, 1, 2)) groups--;
console.log(groups);
```

출력은 `true`, `false`, `1`입니다. n과 사람 번호는 유효한 정수라고 가정합니다. 배열을 함수에 전달할 뿐 클래스를 만들 필요는 없습니다.

| 작업 | parent | size | 팀 수 |
| --- | --- | --- | --- |
| 시작 | `[0,1,2]` | `[1,1,1]` | 3 |
| 0과 1 합침 | `[0,0,2]` | `[2,1,1]` | 2 |
| 1과 2 합침 | `[0,0,0]` | `[3,1,1]` | 1 |

두 번째 연결에서 1의 대표자는 0입니다. 그래서 2를 1 아래 붙이는 대신 대표자 0 아래 붙입니다. size는 **대표자 위치의 값만 팀 크기로 사용**합니다. 1번 위치의 1은 이제 팀 크기를 의미하지 않습니다.

같은 두 사람을 다시 합치면 false가 됩니다. 그래서 true일 때만 groups를 줄여야 합니다. parent와 size는 연결 작업 사이에 유지해야 하고, 매번 초기화하면 이전 팀 정보를 잃습니다.

## 부모를 바로 비교하면 안 되는 경우

더 큰 예제에서는 3이 2를, 2가 0을 가리킬 수도 있습니다. `parent[3]`은 2여도 대표자는 0입니다. 같은 팀 확인은 **parent의 값이 아니라 find의 결과**로 해야 합니다.

경로를 줄이는 방법과 크기 기준 합치기를 함께 쓰면 연산당 상각 시간은 O(α(n))입니다. 실용적인 크기에서 매우 작은 값이지만, 정확히 O(1)과 같은 뜻은 아닙니다. 저장 공간은 O(n)입니다.

이 구조가 알려주는 것은 같은 팀인지 여부입니다. 최단 경로를 구하거나, 연결을 삭제해 팀을 나누는 기능은 이번 구현에 없습니다.
