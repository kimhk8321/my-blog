이런 코드를 쓰면 네트워크 탭에 요청이 끝없이 쌓입니다.

```jsx
function SearchResults({ query }) {
  const [results, setResults] = useState([]);
  const options = { query, limit: 10 };   // 렌더마다 새 객체

  useEffect(() => {
    fetchResults(options).then(setResults);
  }, [options]);

  return <ResultList items={results} />;
}
```

`query`는 그대로인데 왜 Effect가 계속 다시 실행될까요? 그렇다고 의존성 배열에서 `options`를 빼면 린트가 경고를 띄웁니다. 이번 글은 이 상황이 왜 생기는지, 의존성을 빼지 않고 어떻게 해결하는지 정리합니다.

## React는 의존성을 Object.is로 비교한다

`useEffect`는 렌더가 끝난 뒤, **의존성 배열의 값 중 하나라도 이전 렌더와 달라졌으면** Effect를 다시 실행합니다. 이때 "달라졌다"는 `Object.is`로 판단합니다. 1편에서 본 것처럼 객체는 **내용이 아니라 참조**로 비교됩니다.

```js
function depsChanged(prevDeps, nextDeps) {
  return nextDeps.some((dep, i) => !Object.is(dep, prevDeps[i]));
}

const renderOptions = (query) => [{ query, limit: 10 }];   // 렌더마다 새 객체를 만듦

console.log(depsChanged(renderOptions("react"), renderOptions("react"))); // true
console.log(depsChanged(["react", 10], ["react", 10])); // false
```

내용이 똑같은 `{ query: "react", limit: 10 }`이어도 **렌더마다 새로 만든 객체**라 참조가 다르고, React는 "바뀌었다"고 판단합니다. 반면 문자열이나 숫자 같은 원시값은 값이 같으면 같다고 봅니다.

## 무한 루프가 되는 과정

처음 코드를 따라가 봅시다.

1. 렌더: `options` 객체가 새로 만들어집니다.
2. Effect 실행: 이전 렌더가 없으니 실행. 요청을 보냅니다.
3. 응답 도착: `setResults(새 배열)` → 리렌더.
4. 렌더: `options` 객체가 **또 새로** 만들어집니다.
5. Effect 비교: 이전 `options`와 참조가 다름 → **다시 실행.** 요청을 또 보냅니다.
6. 3번으로 돌아감.

Effect 안에서 state를 바꾸고, 그 리렌더 때문에 의존성이 또 바뀌는 순환입니다. 함수도 똑같습니다. 컴포넌트 안에서 선언한 함수는 렌더마다 새 함수라서, 의존성에 넣으면 매번 바뀐 것으로 판단됩니다.

## 그럼 의존성에서 빼면 되지 않나

```jsx
useEffect(() => {
  fetchResults({ query, limit: 10 }).then(setResults);
}, []);   // 의존성을 비움
```

무한 루프는 사라지지만 이번에는 **`query`가 바뀌어도 다시 검색하지 않습니다.** 7편에서 본 것처럼 Effect 함수는 처음 렌더의 `query`를 클로저로 기억한 채 다시 실행되지 않으니까요. 의존성 배열은 성능 옵션이 아니라 **"이 Effect가 어떤 값을 읽는지"를 React에 알려 주는 목록**입니다. Effect 안에서 읽는 props, state, 그것으로 만든 값은 모두 들어가야 합니다. 그래서 린트 규칙(`react-hooks/exhaustive-deps`)이 빠진 값을 경고합니다.

해결 방향은 의존성을 **빼는 게 아니라, 의존성이 진짜 바뀔 때만 바뀌게 만드는 것**입니다.

## 해결 방법 (좋은 것부터)

### 1. 객체를 Effect 안에서 만든다

```jsx
useEffect(() => {
  const options = { query, limit: 10 };   // Effect 안으로 옮김
  fetchResults(options).then(setResults);
}, [query]);   // 원시값만 의존
```

Effect에서만 쓰는 객체라면 Effect 안에서 만들면 됩니다. 의존성은 객체를 만드는 재료인 `query`가 되고, `query`는 문자열이라 값이 같으면 같다고 판단됩니다. 가장 먼저 시도할 방법입니다.

### 2. 객체 대신 원시값을 의존성으로

props로 객체를 받는 경우에는 객체 전체 대신 **필요한 필드만** 꺼내서 의존합니다.

```jsx
function SearchResults({ filter }) {
  const { query, limit } = filter;
  useEffect(() => {
    fetchResults({ query, limit }).then(setResults);
  }, [query, limit]);
}
```

부모가 매번 새 `filter` 객체를 넘겨도, 안의 값이 같으면 Effect는 다시 실행되지 않습니다.

### 3. 함수는 Effect 안이나 컴포넌트 밖으로

```jsx
// props나 state를 쓰지 않는 함수는 컴포넌트 밖에
function buildUrl(query) {
  return `/api/search?q=${encodeURIComponent(query)}`;
}

function SearchResults({ query }) {
  useEffect(() => {
    fetch(buildUrl(query)).then(/* ... */);
  }, [query]);   // buildUrl은 렌더마다 바뀌지 않으니 의존성이 아님
}
```

컴포넌트 밖에 있는 함수는 렌더와 상관없이 **항상 같은 함수**입니다. props나 state를 써야 하는 함수라면 Effect 안으로 옮깁니다.

### 4. 업데이터 함수로 state 의존성을 없앤다

```jsx
useEffect(() => {
  const id = setInterval(() => {
    setCount((c) => c + 1);   // count를 읽지 않음
  }, 1000);
  return () => clearInterval(id);
}, []);   // count가 의존성에 없어도 됨
```

7편의 업데이터 함수를 쓰면 Effect가 `count`를 읽지 않아도 되니, `count`가 바뀔 때마다 interval을 다시 만들 필요가 없습니다.

### 5. 정말 같은 참조가 필요하면 useMemo, useCallback

```jsx
const options = useMemo(() => ({ query, limit: 10 }), [query]);
```

`options`를 Effect뿐 아니라 자식 컴포넌트에도 넘겨야 한다면, `useMemo`로 `query`가 바뀔 때만 새 객체를 만들게 합니다. 함수는 `useCallback`입니다. 1~4번으로 해결할 수 없을 때 씁니다. React Compiler를 켜면 이런 메모이제이션을 빌드할 때 자동으로 넣어 주지만, 의존성이 무엇인지 이해하고 있어야 하는 건 같습니다.

### 6. 읽기만 하고 다시 실행하고 싶지 않은 값은 useEffectEvent

```jsx
function ChatRoom({ roomId, theme }) {
  const onConnected = useEffectEvent(() => {
    showNotification("연결됨", theme);   // 최신 theme을 읽음
  });

  useEffect(() => {
    const connection = createConnection(roomId);
    connection.on("connected", onConnected);
    connection.connect();
    return () => connection.disconnect();
  }, [roomId]);   // theme이 바뀌어도 다시 연결하지 않음
}
```

테마가 바뀌었다고 채팅방에 다시 연결할 필요는 없습니다. React 19.2의 `useEffectEvent`로 감싼 함수는 **항상 최신 값을 읽지만 의존성에는 들어가지 않습니다.** "Effect를 다시 실행할 이유"가 되는 값(`roomId`)과 "실행될 때 읽기만 할 값"(`theme`)을 나누는 도구입니다. 린트 경고를 피하려고 아무 함수나 감싸는 용도로 쓰지 않습니다.

## 애초에 Effect가 필요 없는 경우

의존성 문제를 풀다 보면 Effect 자체가 필요 없는 경우도 많습니다.

```jsx
// 불필요한 Effect: props로 계산할 수 있는 값을 state에 복사
const [fullName, setFullName] = useState("");
useEffect(() => {
  setFullName(`${first} ${last}`);
}, [first, last]);

// 렌더 중에 계산하면 됨
const fullName = `${first} ${last}`;
```

props나 state로 계산할 수 있는 값은 렌더 중에 계산하고, 클릭처럼 사용자 동작으로 시작하는 일은 이벤트 핸들러에서 합니다. Effect는 **React 바깥(네트워크, 구독, 타이머, DOM API)과 맞출 때**만 씁니다.

## 정리

| 원인 | 해결 |
| --- | --- |
| 렌더 중에 만든 객체를 의존 | 객체를 Effect 안에서 만들고 원시값에 의존 |
| props로 받은 객체를 의존 | 필요한 필드만 꺼내서 의존 |
| 컴포넌트 안의 함수를 의존 | Effect 안이나 컴포넌트 밖으로 옮김 |
| state를 읽어서 갱신 | 업데이터 함수로 바꿔 의존성에서 제거 |
| 같은 참조를 여러 곳에서 써야 함 | useMemo, useCallback |
| 읽기만 하고 재실행은 원치 않음 | useEffectEvent |

> "useEffect는 의존성 배열의 값을 이전 렌더와 Object.is로 비교하는데, 객체와 함수는 참조로 비교되기 때문에 렌더 중에 새로 만들면 내용이 같아도 매번 바뀐 것으로 판단됩니다. Effect 안에서 state를 바꾸면 그 리렌더로 의존성이 또 바뀌어 무한 루프가 됩니다. 의존성을 빼면 오래된 값을 읽는 버그가 생기므로, 객체를 Effect 안에서 만들어 원시값에 의존하거나, 함수를 밖으로 옮기거나, 업데이터 함수와 useEffectEvent로 의존할 필요 자체를 없앱니다."
