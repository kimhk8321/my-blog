VS Code, Linear, Notion, GitHub… 요즘 잘 만든 앱은 대부분 **⌘K 커맨드 팔레트**를 가지고 있습니다. 아무 화면에서나 단축키 하나로 명령·검색·이동을 해결하는 이 패턴은, 파워 유저에게는 마우스보다 빠른 길이죠.

만드는 데 필요한 건 세 가지입니다 — **퍼지 검색**, **키보드 내비게이션**, 그리고 **오버레이 UX**. 하나씩 짜 봅니다.

## 퍼지 검색 — 부분 순서 매칭

퍼지 검색의 가장 단순하고 효과적인 형태는 **부분 순서 매칭(subsequence match)** 입니다. "쿼리의 글자들이 순서대로(연속일 필요 없이) 텍스트에 나타나는가?"를 봅니다.

```js
function fuzzyMatch(query, text) {
  const q = query.toLowerCase();
  const t = text.toLowerCase();
  let qi = 0;
  for (const ch of t) {
    if (ch === q[qi]) qi++;      // 글자가 순서대로 걸리면 다음으로
    if (qi === q.length) return true;
  }
  return qi === q.length;
}

fuzzyMatch("cmd", "command palette"); // true (c...m...d)
fuzzyMatch("ㄷㅋ", "다크 모드");       // false — "ㄷ"과 "다"는 다른 글자
```

`command`에서 `cmd`를 치면 `c`, `m`, `d`가 순서대로 발견돼 매칭됩니다. 이 단순한 규칙만으로도 "생각나는 글자 몇 개"로 명령을 찾는 경험이 만들어집니다.

### 한글이라면 초성 매칭까지

그런데 위 함수로는 `ㄷㅋ`이 "다크"에 걸리지 않습니다. 글자를 그대로 비교하면 `ㄷ`과 `다`는 전혀 다른 문자거든요. 한국어 사용자에게 퍼지 검색은 사실상 **초성 검색**이라, 텍스트 쪽 글자를 초성으로 바꿔서도 비교해야 합니다.

한글 음절(가~힣)은 유니코드에서 `초성 × 588 + 중성 × 28 + 종성` 규칙으로 배치돼 있어서, 계산 한 번으로 초성을 꺼낼 수 있습니다.

```js
const CHOSUNG = "ㄱㄲㄴㄷㄸㄹㅁㅂㅃㅅㅆㅇㅈㅉㅊㅋㅌㅍㅎ";

function toChosung(ch) {
  const offset = ch.charCodeAt(0) - 0xac00; // "가"의 코드
  if (offset < 0 || offset > 11171) return ch; // 한글 음절이 아니면 그대로
  return CHOSUNG[Math.floor(offset / 588)];
}

function fuzzyMatch(query, text) {
  const q = [...query.toLowerCase().replace(/\s/g, "")];
  let qi = 0;
  for (const ch of text.toLowerCase()) {
    // 글자가 같거나, 초성이 같으면 매칭
    if (ch === q[qi] || toChosung(ch) === q[qi]) qi++;
    if (qi === q.length) return true;
  }
  return qi === q.length;
}

fuzzyMatch("ㄷㅋ", "다크 모드");   // true (다→ㄷ, 크→ㅋ)
fuzzyMatch("다ㅋ", "다크 모드");   // true (글자와 초성을 섞어도 됨)
```

검색어의 공백을 지운 것도 작은 배려입니다. "다크 모드"를 띄어 치든 붙여 치든 같은 결과가 나옵니다.

실전에서는 여기에 **점수(score)** 를 매깁니다 — 연속으로 매칭될수록, 단어 첫 글자에 매칭될수록 높은 점수를 줘서 정렬하죠. `fzf`, `fuse.js`가 이 점수 로직을 정교하게 다듬은 라이브러리입니다.

## 키보드 내비게이션 — active 인덱스

목록을 키보드로 다루는 핵심은 **"지금 몇 번째가 활성인가"(active index)** 하나입니다. 화살표로 이 인덱스를 옮기고, Enter로 그 항목을 선택합니다.

```jsx
const [active, setActive] = useState(0);

const onKeyDown = (e) => {
  if (e.key === "ArrowDown") {
    e.preventDefault(); // 페이지 스크롤 방지
    setActive((a) => Math.min(a + 1, filtered.length - 1));
  } else if (e.key === "ArrowUp") {
    e.preventDefault();
    setActive((a) => Math.max(a - 1, 0));
  } else if (e.key === "Enter") {
    choose(filtered[active]);
  } else if (e.key === "Escape") {
    close();
  }
};
```

주의할 디테일: 검색어가 바뀌어 목록이 줄어들면 `active`가 범위를 벗어날 수 있습니다. 쿼리가 바뀔 때 `active`를 0으로 리셋하면 안전합니다.

```jsx
useEffect(() => setActive(0), [query]);
```

`ArrowDown`/`ArrowUp`에서 `preventDefault()`를 부르는 것도 중요합니다 — 안 그러면 화살표가 팔레트 이동과 **페이지 스크롤을 동시에** 일으킵니다.

### 활성 항목을 화면 안에 유지하기

`preventDefault()`로 기본 스크롤을 막았으니, 이제 목록 스크롤은 직접 책임져야 합니다. 목록 높이를 넘는 항목으로 내려가면 하이라이트가 보이지 않는 곳으로 사라지거든요. 활성 항목이 바뀔 때마다 위아래로 벗어났는지 보고 **벗어난 만큼만** 스크롤합니다.

```jsx
useEffect(() => {
  const list = listRef.current;
  const item = list?.children[active];
  if (!list || !item) return;
  if (item.offsetTop < list.scrollTop) {
    list.scrollTop = item.offsetTop; // 위로 벗어남 → 위쪽에 맞춤
  } else if (item.offsetTop + item.offsetHeight > list.scrollTop + list.clientHeight) {
    list.scrollTop = item.offsetTop + item.offsetHeight - list.clientHeight; // 아래로 벗어남
  }
}, [active]);
```

`item.scrollIntoView({ block: "nearest" })`로도 비슷하게 되지만, 목록을 감싼 페이지까지 함께 스크롤될 수 있어서 목록의 `scrollTop`만 조절했습니다. `offsetTop`이 목록 기준으로 계산되도록 목록(`ul`)에 `position: relative`를 주고, "결과 없음" 같은 안내 문구는 목록 밖에 둬서 `children[active]`가 항목과 정확히 맞게 합니다.

### 한글 입력 중의 Enter

한국어 IME는 글자를 조합하는 동안에도 keydown 이벤트를 보냅니다. "다크"를 치고 바로 Enter를 누르면, 아직 조합 중인 "크"를 확정하는 Enter가 **선택 동작까지 실행**해 버릴 수 있죠. 조합 중인 키 입력은 IME에 맡기고 무시합니다.

```jsx
const onKeyDown = (e) => {
  if (e.nativeEvent.isComposing) return; // 한글 조합 중이면 건너뜀
  // ...화살표·Enter·Esc 처리
};
```

## 열고 닫기 — 포커스 관리

팔레트가 뜨면 **입력창에 자동 포커스**가 가야 바로 타이핑할 수 있습니다.

```jsx
useEffect(() => {
  if (open) inputRef.current?.focus();
}, [open]);
```

그리고 이건 사실상 [접근 가능한 모달](/posts/accessible-modal)입니다 — 배경 클릭으로 닫기, Esc로 닫기, 포커스 트랩, 닫을 때 원래 위치로 포커스 복귀까지 챙기면 완성도가 올라갑니다. 커맨드 팔레트는 "모달 + 검색 + 키보드 목록"의 합성이라고 봐도 됩니다.

포커스 복귀에는 함정이 하나 있습니다. Enter로 항목을 고르는 순간 포커스를 "팔레트 열기" 버튼으로 돌려주면, **같은 Enter 키의 기본 동작이 그 버튼을 눌러** 팔레트가 곧바로 다시 열립니다. Enter를 처리할 때도 `e.preventDefault()`를 불러 기본 동작을 끊어야 합니다.

## 전역 단축키 — ⌘K 바인딩

어느 화면에서나 열리려면 전역 키 리스너가 필요합니다. `metaKey`(맥)와 `ctrlKey`(윈도우)를 함께 봅니다.

```jsx
useEffect(() => {
  const onKey = (e) => {
    if ((e.metaKey || e.ctrlKey) && e.key === "k") {
      e.preventDefault(); // 브라우저 기본 동작 차단
      setOpen((o) => !o);
    }
  };
  window.addEventListener("keydown", onKey);
  return () => window.removeEventListener("keydown", onKey);
}, []);
```

`preventDefault`가 없으면 브라우저의 기본 단축키와 충돌합니다. 윈도우 크롬에서 Ctrl+K는 주소창 검색을 여는 키라서, 이 처리가 빠지면 팔레트 대신 크롬 검색이 뜹니다. Caps Lock이 켜져 있으면 `e.key`가 대문자 `"K"`가 되므로 `e.key.toLowerCase()`로 비교하면 더 안전합니다. 위 데모도 이 리스너가 붙어 있어서, 이 페이지 어디서든 단축키로 팔레트가 열립니다.

## 접근성 한 가지

목록을 스크린 리더가 이해하려면 `role="listbox"`/`role="option"`과 `aria-activedescendant`로 "지금 몇 번째가 활성인지"를 알려야 합니다. 마우스 사용자에겐 안 보이지만, 키보드·스크린 리더 사용자에겐 이게 팔레트를 쓸 수 있느냐를 가릅니다.
