계좌 이체를 생각해 봅시다. A에서 1만 원을 빼고 B에 1만 원을 더한다. 그런데 빼는 데는 성공하고 **더하는 도중 서버가 죽으면?** 돈이 증발합니다. 이런 "전부 아니면 전무"를 보장하는 게 **트랜잭션**입니다. 그리고 여러 사용자가 동시에 데이터를 건드릴 때 생기는 혼란을 다루는 게 **격리 수준**이죠.

## 트랜잭션 — ACID

트랜잭션은 여러 작업을 **하나의 단위**로 묶습니다. 그 성질이 ACID입니다. ([CS의 트랜잭션](/posts/cs-database) 편과 이어집니다.)

- **원자성(Atomicity)**: 전부 성공하거나 전부 취소. 중간 실패 시 **롤백**.
- **일관성(Consistency)**: 규칙(제약조건)을 항상 만족.
- **격리성(Isolation)**: 동시에 실행돼도 서로 간섭하지 않는 것처럼.
- **지속성(Durability)**: 커밋되면 장애가 나도 남는다.

```sql
BEGIN;
UPDATE accounts SET balance = balance - 10000 WHERE id = 'A';
UPDATE accounts SET balance = balance + 10000 WHERE id = 'B';
COMMIT;  -- 둘 다 성공해야 확정. 하나라도 실패하면 ROLLBACK.
```

## 동시성이 만드는 문제들

여러 트랜잭션이 겹치면 이런 이상 현상이 생깁니다.

- **Dirty Read**: 아직 커밋 안 된 남의 변경을 읽음(그 변경이 롤백되면 유령 데이터).
- **Non-repeatable Read**: 같은 행을 두 번 읽었는데 사이에 남이 바꿔서 값이 다름.
- **Phantom Read**: 같은 조건으로 두 번 조회했는데 사이에 행이 추가/삭제돼 결과 개수가 다름.
- **Lost Update**: 둘이 동시에 읽고 각자 수정·저장 → 한쪽 변경이 덮여 사라짐.

## 격리 수준 — 일관성 vs 성능

격리 수준은 "이 이상 현상들을 어디까지 막을까"의 단계입니다. 강할수록 안전하지만 느립니다.

| 수준 | Dirty | Non-repeatable | Phantom |
| --- | --- | --- | --- |
| Read Uncommitted | 허용 | 허용 | 허용 |
| Read Committed | 방지 | 허용 | 허용 |
| Repeatable Read | 방지 | 방지 | 허용* |
| Serializable | 방지 | 방지 | 방지 |

강한 격리는 락·검증 비용이 커져 처리량이 떨어집니다. 그래서 대부분의 DB 기본값은 **Read Committed**(PostgreSQL) 또는 **Repeatable Read**(MySQL) — "충분히 안전하되 너무 느리지 않은" 절충점입니다.

## 락 — 비관적 vs 낙관적

Lost Update를 막는 두 전략이 있습니다.

**비관적 락(Pessimistic)**: "충돌이 날 거야" 가정하고 **먼저 잠근다**. 읽을 때 `SELECT ... FOR UPDATE`로 행을 잠가 남이 못 건드리게. 확실하지만 대기·데드락 위험.

**낙관적 락(Optimistic)**: "충돌은 드물 거야" 가정하고 **잠그지 않되, 저장 시 검증**. 버전 컬럼을 두고, 저장할 때 "내가 읽은 버전이 그대로면 저장, 아니면 실패":

```sql
UPDATE posts SET content = ?, version = version + 1
WHERE id = ? AND version = ?;  -- 영향받은 행이 0이면 = 그새 누가 바꿈 → 재시도
```

> 프론트의 [낙관적 업데이트](/posts/optimistic-updates)와 이름은 같지만 다릅니다. 프론트는 "UI를 먼저 바꾸고 실패 시 롤백", 여기선 "충돌을 저장 시점에 감지"예요. 발상("낙관적으로 가정")은 통합니다.

## 데드락

두 트랜잭션이 서로가 쥔 락을 기다리면 **교착(deadlock)**. DB가 감지해 한쪽을 강제 롤백합니다. 락을 **항상 같은 순서로** 획득하면 예방할 수 있어요. ([운영체제의 데드락](/posts/cs-operating-system)과 같은 원리.)

---

트랜잭션의 핵심은 "**여러 작업을 하나로, 동시 실행 속에서도 일관되게**"입니다. 격리 수준은 안전과 성능의 다이얼이고, 락은 충돌을 다루는 두 가지 태도죠. 다음 글에서는 그 쿼리가 빠르게 돌게 하는 [인덱스와 N+1 문제](/posts/query-performance)를 봅니다.
