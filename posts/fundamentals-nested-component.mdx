입력칸에 한 글자를 치면 포커스가 풀려서, 다시 클릭해야 다음 글자를 칠 수 있는 버그를 만나 본 적이 있나요? 코드를 보면 이상한 곳이 없어 보입니다.

```jsx
function SignupForm() {
  const [name, setName] = useState("");

  function NameField() {
    return <input value={name} onChange={(e) => setName(e.target.value)} />;
  }

  return (
    <form>
      <NameField />
    </form>
  );
}
```

`NameField`가 `name`을 바로 쓸 수 있으니 편하다고 생각해서 컴포넌트 안에 넣은 코드입니다. 그런데 이 코드가 바로 원인입니다.

## 무슨 일이 일어나나

1. 사용자가 "김"을 입력합니다.
2. `setName("김")` → `SignupForm`이 다시 렌더됩니다.
3. 렌더 중에 `function NameField() {...}`가 **다시 실행되어 새 함수가 만들어집니다.**
4. React가 이전 화면과 새 화면을 비교합니다. 이전 자리에는 "이전 NameField", 새 자리에는 "새 NameField"가 있습니다.
5. **둘은 다른 함수**라서, React는 다른 컴포넌트로 판단합니다.
6. 이전 `<input>`을 DOM에서 지우고, 새 `<input>`을 만들어 붙입니다.
7. 포커스는 지워진 input에 있었으니 **사라집니다.**

화면에서는 같은 입력칸처럼 보이지만, 실제로는 **글자를 칠 때마다 입력칸이 새로 만들어지고 있는 것**입니다.

## 컴포넌트의 타입은 함수의 참조다

`<NameField />`라고 쓰면 React는 이런 객체를 만듭니다.

```js
{ type: NameField, props: {} }
```

`type`에 들어가는 건 **함수 그 자체(참조)** 입니다. 9편에서 본 재조정의 첫 번째 규칙은 "같은 자리에 같은 타입이면 유지, 다르면 새로 만든다"였습니다. 이 "같은 타입"을 판단할 때 React는 함수를 **참조로 비교**합니다.

그리고 1편에서 본 것처럼 함수도 객체라서, 같은 코드라도 **새로 만들면 다른 참조**입니다.

```js
function render() {
  function NameField() {}   // 렌더마다 새로 만들어지는 함수
  return { type: NameField };
}

const first = render();
const second = render();
console.log(first.type === second.type); // false

function StableField() {}   // 컴포넌트 밖에서 한 번만 만들어진 함수
const a = { type: StableField };
const b = { type: StableField };
console.log(a.type === b.type); // true
```

컴포넌트 안에서 정의한 컴포넌트는 렌더마다 `false` 쪽입니다. 매번 "타입이 바뀌었다"고 판단되니, 그 아래의 DOM과 state가 **전부 버려지고 새로 만들어집니다(리마운트).**

## 포커스만 날아가는 게 아니다

리마운트는 생각보다 많은 것을 초기화합니다.

- **DOM:** input의 포커스, 커서 위치, 스크롤 위치가 사라집니다.
- **state:** `NameField` 안에 `useState`가 있었다면 렌더마다 초깃값으로 돌아갑니다.
- **Effect:** 안쪽 컴포넌트의 Effect가 렌더마다 정리됐다가 다시 실행됩니다. 구독이나 요청이 반복됩니다.
- **성능:** 비교해서 바뀐 부분만 고치는 대신 매번 통째로 다시 만듭니다.

## 해결: 컴포넌트는 밖에 정의하고 props로 넘긴다

```jsx
function NameField({ value, onChange }) {
  return <input value={value} onChange={(e) => onChange(e.target.value)} />;
}

function SignupForm() {
  const [name, setName] = useState("");
  return (
    <form>
      <NameField value={name} onChange={setName} />
    </form>
  );
}
```

`NameField`는 이제 파일이 로드될 때 **한 번만** 만들어집니다. 렌더마다 같은 참조라서 React는 같은 컴포넌트로 보고 input을 유지합니다. 바깥 값은 클로저로 읽는 대신 **props로** 받습니다.

### 마크업을 나누고 싶을 뿐이라면 함수로 호출하기

컴포넌트로 만들 필요 없이 JSX 조각만 나누고 싶다면, 컴포넌트가 아니라 **JSX를 돌려주는 일반 함수**로 쓰는 방법도 있습니다.

```jsx
function SignupForm() {
  const [name, setName] = useState("");

  const renderNameField = () => (
    <input value={name} onChange={(e) => setName(e.target.value)} />
  );

  return <form>{renderNameField()}</form>;
}
```

`renderNameField()`는 `<input>` 요소를 그대로 돌려줄 뿐이라, React가 보는 타입은 매번 같은 `"input"`입니다. 그래서 리마운트되지 않습니다. 대신 이 함수 안에서는 훅을 쓸 수 없습니다(8편). 훅이 필요하면 밖에 정의한 컴포넌트로 만듭니다.

## 같은 문제가 생기는 다른 모양들

모두 **렌더 중에 새 컴포넌트(새 타입)를 만든다**는 공통점이 있습니다.

### 렌더 중에 고차 컴포넌트 적용

```jsx
function Page() {
  const EnhancedList = withLoading(List);   // 렌더마다 새 컴포넌트
  return <EnhancedList />;
}
```

`withLoading`이 매번 새 컴포넌트를 돌려주니 매 렌더 리마운트됩니다. 고차 컴포넌트는 **모듈 최상위**에서 한 번 적용합니다.

```jsx
const EnhancedList = withLoading(List);   // 밖에서 한 번
function Page() {
  return <EnhancedList />;
}
```

### 렌더 중에 lazy 호출

```jsx
function Page() {
  const Chart = lazy(() => import("./Chart"));   // 렌더마다 새로 로드 상태로
  return <Chart />;
}
```

`lazy`도 호출할 때마다 새 컴포넌트를 만들어서, 렌더할 때마다 처음부터 다시 불러오는 상태가 됩니다. `lazy`는 모듈 최상위에서 선언합니다.

### 객체나 배열에 컴포넌트를 담아 렌더 중에 만들기

```jsx
function Tabs({ tab }) {
  const panels = {
    home: () => <Home />,
    settings: () => <Settings />,
  };
  const Panel = panels[tab];   // 렌더마다 새 함수
  return <Panel />;
}
```

`panels` 객체를 컴포넌트 밖으로 빼거나, `panels[tab]()`처럼 함수로 호출해 JSX를 꺼내 쓰면 됩니다.

## 린트로 미리 잡기

`eslint-plugin-react`의 `no-unstable-nested-components` 규칙은 컴포넌트 안에서 정의한 컴포넌트를 찾아 경고합니다. 리뷰에서 놓치기 쉬운 패턴이라 켜 두면 좋습니다.

## 반대로, 일부러 새로 만들고 싶다면

리마운트가 필요한 경우도 있습니다. 다른 사용자를 선택했을 때 입력 폼을 완전히 초기화하고 싶다면, 컴포넌트를 안에서 만들 게 아니라 9편에서 본 것처럼 **key를 바꾸는** 게 정석입니다.

```jsx
<ProfileForm key={userId} userId={userId} />
```

타입은 그대로 두고, key로 "다른 항목"이라고 알려 주는 방식입니다.

## 정리

> "JSX의 컴포넌트 타입은 함수의 참조이고, React는 재조정할 때 같은 자리의 타입이 다르면 이전 것을 버리고 새로 만듭니다. 컴포넌트 안에서 컴포넌트를 정의하면 부모가 렌더될 때마다 새 함수가 만들어져 매번 다른 타입으로 판단되므로, 그 아래의 DOM과 state가 리마운트되어 입력 포커스와 상태가 사라집니다. 그래서 컴포넌트와 고차 컴포넌트, lazy는 모듈 최상위에 한 번만 정의하고 값은 props로 넘기며, 일부러 초기화하고 싶을 때는 key를 바꿉니다."
