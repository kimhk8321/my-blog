에디터, 그림판, 폼 빌더… "되돌리기(Undo)"가 필요한 순간은 많습니다. 그런데 막상 구현하려면 막막합니다. 어디까지 기억해야 하고, 되돌린 뒤 새 동작을 하면 "다시 실행(Redo)"은 어떻게 되는 걸까요?

답은 의외로 정갈합니다. **세 개의 스택** — 과거(past), 현재(present), 미래(future) — 만 있으면 됩니다.

## 먼저 만져 보기

+1, ×2 등으로 값을 바꾸고 Undo로 되돌려 보세요. 되돌린 뒤 Redo로 다시 앞으로 갈 수 있고, 되돌린 상태에서 **새 동작**을 하면 Redo 스택이 비워집니다.

## 핵심 모델 — past / present / future

상태를 이렇게 봅니다.

```
past: [0, 1, 2]   present: 4   future: [8, 16]
       ↑ 지나온 값들        ↑ 지금        ↑ 되돌려서 비워둔 앞날
```

- **새 동작(do)**: 현재를 과거에 밀어 넣고, 새 값을 현재로. **미래는 비운다.**
- **Undo**: 과거의 맨 뒤를 꺼내 현재로, 기존 현재는 미래의 맨 앞으로.
- **Redo**: 미래의 맨 앞을 꺼내 현재로, 기존 현재는 과거의 맨 뒤로.

"새 동작을 하면 미래를 비운다"가 핵심 규칙입니다. 3번째 상태로 되돌린 뒤 다른 길을 택하면, 원래 가려던 미래는 더 이상 유효하지 않으니까요.

## useReducer로 구현

이 세 전이는 리듀서로 옮기면 그대로 코드가 됩니다.

```js
function reducer(state, action) {
  const { past, present, future } = state;

  switch (action.type) {
    case "do":
      return { past: [...past, present], present: action.next, future: [] };

    case "undo":
      if (!past.length) return state;
      return {
        past: past.slice(0, -1),
        present: past[past.length - 1],
        future: [present, ...future],
      };

    case "redo":
      if (!future.length) return state;
      return {
        past: [...past, present],
        present: future[0],
        future: future.slice(1),
      };
  }
}
```

`past.length`·`future.length`이 0이면 Undo/Redo를 막는 것도 자연스럽게 처리됩니다. 버튼의 `disabled`도 이 길이로 결정하면 되죠.

```jsx
const [state, dispatch] = useReducer(reducer, {
  past: [], present: initialValue, future: [],
});

<button disabled={!state.past.length} onClick={() => dispatch({ type: "undo" })}>
  Undo
</button>
```

## 커맨드 패턴 — 값이 아니라 '동작'을 저장하기

위 방식은 **상태 스냅샷**을 통째로 저장합니다. 값이 숫자 하나면 괜찮지만, 거대한 문서라면 매 단계 전체를 복사하는 게 부담입니다. 이때 **커맨드 패턴**으로 바꿉니다 — 스냅샷 대신 **역연산이 가능한 동작**을 저장하는 거죠.

```js
// 각 커맨드는 실행(do)과 되돌리기(undo)를 안다
const addText = (text) => ({
  do: (doc) => doc + text,
  undo: (doc) => doc.slice(0, -text.length),
});

// 히스토리엔 커맨드만 쌓는다
history.push(addText("안녕"));
// Undo = 마지막 커맨드의 undo() 호출
```

전체 상태를 복제하는 대신 **변경분(diff)만** 기억하니 메모리가 훨씬 절약됩니다. 텍스트 에디터·그래픽 툴이 이 방식을 씁니다. 대신 모든 동작에 정확한 역연산을 정의해야 하죠.

## 실전에서 더 챙길 것들

- **묶기(batching)**: 타이핑 한 글자마다 히스토리에 쌓으면 Undo가 너무 잘게 쪼개집니다. 일정 시간/단위로 묶어 하나의 스텝으로.
- **한도(limit)**: past가 무한정 커지지 않게 오래된 것부터 버립니다.
- **불변성**: 스냅샷 방식은 상태를 **불변**으로 다뤄야 과거 값이 오염되지 않습니다. ([불변성과 useReducer](/posts/modern-react-arrays-reducer) 글과 연결됩니다.)

라이브러리로는 `immer`의 patches나 `zundo`(zustand용) 등이 이 패턴을 잘 포장해 두었지만, 직접 만들어 보면 그 안에서 무슨 일이 일어나는지 선명해집니다.
