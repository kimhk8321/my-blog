CSS `transition`은 편하지만 한계가 있습니다. `ease-in-out` 같은 정해진 곡선은 **목적지가 도중에 바뀌면** 어색해집니다. 마우스를 따라다니는 요소를 `transition`으로 만들면, 커서가 방향을 틀 때마다 뚝뚝 끊기죠. 자연스러운 움직임은 곡선이 아니라 **물리**에서 나옵니다.

**스프링(용수철) 애니메이션**은 목적지를 정해두지 않습니다. 대신 매 프레임 "현재 위치에서 목표를 향해 당기는 힘"을 계산하죠. Framer Motion, React Spring이 부드럽게 느껴지는 이유가 이겁니다.

## 스프링의 물리 — 세 줄이면 끝

용수철 운동은 세 가지 값으로 표현됩니다.

- **위치(position)**: 지금 어디에 있는가
- **속도(velocity)**: 얼마나 빠르게 움직이는가
- **목표(target)**: 어디로 가려 하는가

매 프레임 이렇게 갱신합니다.

```js
// 목표를 향해 당기는 힘(강성 k)을 속도에 더하고, 감쇠(d)로 줄인다
velocity = (velocity + (target - position) * k) * d;
position = position + velocity;
```

`(target - position)`이 "얼마나 떨어졌나" = 당기는 힘입니다. 멀수록 세게 당겨지죠(훅의 법칙). 여기에 **강성 k**를 곱해 힘의 세기를, **감쇠 d**(1 미만)를 곱해 브레이크를 겁니다. 감쇠가 없으면 영원히 진동하고, 너무 크면 뻣뻣해집니다.

## requestAnimationFrame 루프

이 갱신을 매 프레임 돌리는 게 `requestAnimationFrame`입니다. 브라우저의 화면 갱신 주기(보통 60fps)에 맞춰 콜백을 부르죠.

```jsx
useEffect(() => {
  let raf;
  const loop = () => {
    vel.current.x = (vel.current.x + (target.current.x - pos.current.x) * k) * d;
    pos.current.x += vel.current.x;
    // y도 동일하게…
    box.current.style.transform = `translate(${pos.current.x}px, ${pos.current.y}px)`;
    raf = requestAnimationFrame(loop); // 다음 프레임 예약
  };
  raf = requestAnimationFrame(loop);
  return () => cancelAnimationFrame(raf); // 정리 필수!
}, []);
```

핵심 두 가지:

- **상태가 아니라 ref + DOM 직접 조작.** 프레임마다 `setState`하면 React가 60번 리렌더합니다. 위치는 `ref`에 두고 `style.transform`을 직접 씁니다. ([Signals 글](/posts/signals)에서 본, 리렌더를 피하는 그 발상이죠.)
- **`cancelAnimationFrame`으로 정리.** 언마운트 후에도 루프가 돌면 메모리 누수·에러가 납니다.

## setInterval이 아니라 rAF인 이유

왜 `setInterval(loop, 16)`이 아닐까요?

- **화면 주기에 동기화**: rAF는 브라우저가 실제로 다시 그리기 직전에 불립니다. `setInterval`은 화면과 어긋나 프레임이 찢기거나 버벅입니다.
- **백그라운드 절전**: 탭이 비활성이면 rAF는 멈춥니다. `setInterval`은 계속 돌며 배터리를 낭비하죠.
- **`transform`만 건드리기**: 위치를 `left`/`top`이 아니라 `transform: translate`로 옮기면 레이아웃·페인트를 건너뛰고 **합성(compositing)** 만 일어나 훨씬 부드럽습니다. ([리렌더 최적화](/posts/rerender-optimization)의 성능 원리와 통합니다.)

## 프레임 독립성 — delta time

한 가지 더. 위 코드는 "프레임당" 이동이라, 120fps 모니터에선 2배 빨라집니다. 엄밀하게는 프레임 간 경과 시간(delta)을 반영해야 하죠.

```js
const now = performance.now();
const dt = (now - lastTime) / 16.67; // 60fps 기준 배율
lastTime = now;
position += velocity * dt;
```

데모는 단순화를 위해 생략했지만, 다양한 주사율을 지원하려면 delta time이 정석입니다.
