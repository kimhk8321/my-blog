좋아요 버튼을 누르면 숫자가 바로 올라가야 기분이 좋습니다. 그런데 서버 왕복은 짧아도 수백 밀리초. 그동안 버튼이 멍하니 멈춰 있으면 앱이 느리게 느껴집니다.

**낙관적 업데이트(optimistic update)** 는 이 간극을 메웁니다. "어차피 성공할 테니 UI부터 바꿔두고, 서버 응답은 나중에 맞춘다"는 전략이죠. React 19의 `useOptimistic`은 이 패턴을 훅 하나로 정리해 줍니다. 핵심은 **실패했을 때의 롤백**을 프레임워크가 대신 해준다는 점입니다.

누르면 숫자가 즉시 오르고, 900ms 뒤 서버 응답에 따라 확정됩니다. "실패 시뮬레이션"을 켜고 누르면 잠깐 올랐다가 원래대로 **되돌아옵니다**. 이 롤백을 직접 관리하지 않는 게 포인트입니다.

## 손으로 짜면 생기는 문제

`useOptimistic` 없이 만들면 보통 이렇게 씁니다.

```jsx
const [likes, setLikes] = useState(0);

async function like() {
  setLikes((l) => l + 1); // 낙관적
  try {
    await api.like();
  } catch {
    setLikes((l) => l - 1); // 실패하면 되돌리기
  }
}
```

돌아가긴 합니다. 하지만 요청이 겹치면 금세 꼬입니다. 두 번 빠르게 누르면 `+1`이 두 번 나가고, 하나만 실패하면 `-1`을 어디에 되돌려야 할지 계산이 애매해집니다. "낙관적으로 보여준 값"과 "서버가 확정한 값"이 한 변수(`likes`)에 뒤섞여 있는 게 근본 원인입니다.

## useOptimistic의 발상

`useOptimistic`은 이 둘을 분리합니다.

```jsx
const [likes, setLikes] = useState(0); // 서버가 확정한 진짜 값
const [optimisticLikes, addOptimistic] = useOptimistic(
  likes,
  (current, delta) => current + delta, // 낙관적 값을 만드는 방법
);
```

- `likes`는 **실제 상태**. 서버 응답으로만 바뀝니다.
- `optimisticLikes`는 **화면에 보여줄 값**. 평소엔 `likes`와 같지만, 트랜잭션이 진행되는 동안만 낙관적으로 부풀어 오릅니다.
- `addOptimistic(1)`을 부르면 리듀서가 `current + 1`을 만들어 즉시 반영합니다.

여기서 규칙이 하나 있습니다. **`addOptimistic`은 트랜잭션 안에서 불러야** 합니다. 낙관적 값의 수명이 곧 트랜잭션의 수명이기 때문입니다.

```jsx
const [isPending, startTransition] = useTransition();

function like() {
  startTransition(async () => {
    addOptimistic(1);              // 트랜잭션 시작 → 화면에 즉시 +1
    const ok = await api.like();   // 서버 왕복
    if (ok) setLikes((l) => l + 1); // 성공 → 진짜 값 커밋
    // 실패면 아무것도 안 함
  });
}
```

트랜잭션이 끝나는 순간 React는 낙관적 값을 버리고 `optimisticLikes`를 다시 `likes`에 맞춥니다. 그래서 **성공했으면** 방금 커밋한 값으로 자연스럽게 이어지고, **실패했으면** 손대지 않은 `likes`로 되돌아갑니다. 롤백 코드를 한 줄도 쓰지 않았다는 걸 눈여겨보세요.

## 왜 트랜잭션이 열쇠인가

낙관적 값은 "잠깐만 진실인 척하는 값"입니다. 그 "잠깐"의 경계를 React가 알아야 언제 걷어낼지 판단할 수 있는데, 그 경계가 바로 트랜잭션입니다. `isPending`으로 "저장 중" 표시까지 공짜로 얻습니다.

요청이 여러 개 겹쳐도 안전합니다. 각 트랜잭션이 자기 몫의 낙관적 변화를 리듀서에 쌓고, 끝나는 순서대로 정리되기 때문에 아까처럼 `-1`을 어디에 꽂을지 고민할 일이 없습니다.

## 폼과 함께라면 더 짧아진다

Server Actions와 엮으면 `startTransition`조차 직접 부를 필요가 없습니다. `<form action={...}>`이 제출 자체를 트랜잭션으로 감싸주기 때문입니다.

```jsx
function CommentBox({ comments, addComment }) {
  const [optimistic, addOptimistic] = useOptimistic(
    comments,
    (list, text) => [...list, { text, sending: true }],
  );

  async function action(formData) {
    const text = formData.get("text");
    addOptimistic(text);        // 목록에 회색 댓글로 즉시 추가
    await addComment(text);     // 서버 반영
  }

  return (
    <form action={action}>
      {optimistic.map((c, i) => (
        <p key={i} style={{ opacity: c.sending ? 0.5 : 1 }}>{c.text}</p>
      ))}
      <input name="text" />
    </form>
  );
}
```

댓글이 전송되는 동안 반투명으로 먼저 뜨고, 서버가 받아들이면 목록이 실제 데이터로 교체됩니다. 실패하면 그 회색 댓글이 조용히 사라지죠.
