파일 탐색기, 댓글 스레드, 조직도, 중첩 메뉴… 이들의 공통점은 **깊이를 미리 알 수 없는 계층 구조**라는 겁니다. 폴더 안에 폴더가 몇 단계나 있을지 모르는데, 반복문 몇 개로는 이걸 그릴 수 없죠.

답은 **재귀**입니다. 함수가 자기 자신을 부르듯, **컴포넌트가 자기 자신을 렌더링**하면 깊이가 몇이든 자연스럽게 펼쳐집니다.

## 재귀 컴포넌트의 핵심

트리 데이터는 자기 참조적입니다 — 노드가 같은 타입의 자식들을 가집니다.

```ts
type TreeNode = { name: string; children?: TreeNode[] };
```

이걸 그리는 컴포넌트도 똑같이 자기 참조적입니다. **자식을 그릴 때 자기 자신(`Node`)을 부릅니다.**

```jsx
function Node({ node, depth }) {
  const isDir = !!node.children;
  const [open, setOpen] = useState(depth < 1);

  return (
    <div>
      <button onClick={() => isDir && setOpen((o) => !o)}
              style={{ paddingLeft: depth * 16 }}>
        {isDir ? (open ? "▾" : "▸") : ""} {node.name}
      </button>

      {isDir && open &&
        node.children.map((child) => (
          <Node key={child.name} node={child} depth={depth + 1} /> // ← 자기 자신 호출
        ))}
    </div>
  );
}
```

`<Node>`가 자식마다 다시 `<Node>`를 그립니다. 이게 재귀의 전부예요. `depth`를 하나씩 늘려 넘기면 들여쓰기와 "몇 단계인지"를 알 수 있습니다.

## 종료 조건 — 무한 재귀를 막는 것

모든 재귀엔 **바닥(base case)** 이 필요합니다. 없으면 영원히 자신을 부르다 멈추죠. 트리에선 **자식이 없는 노드(잎)** 가 바닥입니다.

```jsx
{isDir && open && node.children.map(...)}
```

`isDir`가 false면(=`children`이 없으면) 더 이상 `<Node>`를 그리지 않습니다. 잎에서 재귀가 자연스럽게 멈춥니다. 데이터가 유한한 트리라면 종료가 보장되죠.

> ⚠️ 단, 데이터에 **순환 참조**(A가 B를, B가 다시 A를 자식으로)가 있으면 무한 렌더링에 빠집니다. 외부에서 온 데이터라면 순환이 없는지 확인하거나, 방문한 노드를 추적해야 합니다.

## 상태를 어디에 둘까

"펼침/접힘"을 어떻게 관리하느냐가 설계 포인트입니다. 두 가지 방식이 있습니다.

**① 각 노드가 자기 상태를 가짐** (데모 방식)

```jsx
const [open, setOpen] = useState(depth < 1);
```

간단하고, 각 노드가 독립적입니다. 단점은 "전부 펼치기/접기" 같은 **바깥에서의 제어**가 어렵고, 리렌더 시 상태가 트리 구조에 흩어져 있다는 점입니다.

**② 바깥에서 열린 노드 집합을 관리**

```jsx
const [openIds, setOpenIds] = useState(new Set());
// <Node open={openIds.has(node.id)} onToggle={...} />
```

"전부 펼치기", 상태 저장·복원, 검색 시 자동 펼침 같은 기능이 필요하면 이 방식이 낫습니다. 상태를 한곳에서 관리하니까요. ([상태를 끌어올리는](/posts/rerender-optimization) 고전적 트레이드오프입니다.)

## key와 성능

재귀에서도 `key`는 중요합니다. 형제 노드를 구분하는 안정적인 값(이름이 겹칠 수 있으면 경로나 id)을 주어야 React가 올바르게 재사용합니다. ([가상 DOM 재조정](/posts/virtual-dom-reconciliation)에서 다룬 그 이유죠.)

노드가 수천 개로 커지면 접힌 가지는 렌더하지 않는 것만으로도 큰 절약이 됩니다. 그보다 커지면 [가상 리스트](/posts/virtual-list-windowing)와 결합해 보이는 노드만 그리는 기법이 필요합니다.
