[CSS 동작 원리](/posts/css-cascade-specificity)에서 캐스케이드와 명시도를 정리하면서 "명시도 싸움은 피곤하다"고 썼습니다. 그때 쓰던 우회법(BEM, `!important`)들 중 상당수가 이제는 **CSS 자체 기능으로** 해결됩니다. 최근 몇 년의 변화를 모아 봅니다.

## :has() — 드디어 부모 선택자

CSS의 오랜 숙원이었습니다. "자식이 이러이러하면 부모를 이렇게"가 안 됐거든요. `:has()`가 그걸 해결합니다.

```css
/* 이미지를 품은 카드만 다르게 */
.card:has(img) { padding: 0; }

/* 체크된 입력을 가진 라벨 */
label:has(input:checked) { font-weight: 600; }

/* 에러 메시지가 있는 폼 그룹 */
.field:has(.error) { border-color: red; }
```

이전에는 이런 걸 하려면 **자바스크립트로 클래스를 붙였습니다.** 상태에 따라 `classList.toggle`을 호출하던 코드가 통째로 사라지죠.

조합하면 더 강력합니다.

```css
/* 다음 형제가 특정 요소일 때 */
h2:has(+ p) { margin-bottom: 0.5rem; }

/* 특정 자식이 없을 때 */
.list:not(:has(li)) { display: none; }  /* 빈 목록 숨기기 */
```

주의할 점은 **명시도**입니다. `:has()` 자체는 명시도를 더하지 않지만, **괄호 안에서 가장 높은 것**이 계산에 들어갑니다.

## 중첩(Nesting) — 전처리기 없이

Sass의 대표 기능이던 중첩이 CSS에 들어왔습니다.

```css
.card {
  padding: 1rem;

  & .title { font-weight: 600; }

  &:hover { border-color: currentColor; }

  @media (width >= 768px) {
    padding: 2rem;
  }
}
```

`&`는 부모 선택자를 가리킵니다. 미디어 쿼리도 안에 넣을 수 있어서, **한 컴포넌트의 규칙이 한자리에 모입니다.**

다만 Sass 시절의 교훈은 그대로예요 — **너무 깊게 중첩하지 말 것**. 3단계를 넘어가면 명시도가 치솟고 어떤 선택자가 만들어지는지 읽기 어려워집니다.

참고로 위 미디어 쿼리에 쓴 `width >= 768px`도 새 문법입니다. `min-width`보다 직관적이죠.

## @layer — 명시도 싸움 끝내기

가장 구조적인 변화입니다. **캐스케이드 레이어**는 "어떤 규칙 뭉치가 어떤 뭉치를 이기는지"를 **명시도와 무관하게** 정합니다.

```css
@layer reset, base, components, utilities;

@layer components {
  .btn { background: blue; }        /* 명시도 0,1,0 */
}

@layer utilities {
  .bg-red { background: red; }      /* 명시도 0,1,0 — 같지만 */
}
```

레이어 순서가 나중일수록 이깁니다. 위에서 `utilities`가 뒤에 선언됐으니, **명시도가 같아도 `.bg-red`가 이깁니다.** 심지어 앞 레이어의 명시도가 더 높아도 뒤 레이어가 이겨요.

이게 왜 중요하냐면:

- **외부 라이브러리 CSS를 낮은 레이어에** 넣으면, 내 스타일이 항상 이깁니다. `!important` 남발이 사라져요.
- **유틸리티 클래스가 컴포넌트 스타일을 이기게** 하는 게 자연스러워집니다. [Tailwind](/posts/tailwind-css)가 v4에서 레이어를 쓰는 이유죠.

레이어에 속하지 않은 스타일은 **모든 레이어보다 강합니다.** 그래서 점진적 도입이 가능해요 — 기존 코드는 그대로 두고 라이브러리만 레이어로 감싸면 됩니다.

## :is()와 :where() — 반복 줄이기

```css
/* 이전 */
.content h1, .content h2, .content h3 { margin-top: 2rem; }

/* :is()로 */
.content :is(h1, h2, h3) { margin-top: 2rem; }
```

둘의 차이는 **명시도**입니다.

- `:is()` — 괄호 안 **가장 높은** 명시도를 가져감
- `:where()` — 명시도가 **항상 0**

`:where()`는 "덮어쓰기 쉬운 기본값"을 만들 때 좋습니다. 리셋 CSS나 라이브러리 기본 스타일에 쓰면 사용자가 손쉽게 재정의할 수 있죠.

```css
:where(button) { all: unset; cursor: pointer; }  /* 누구나 쉽게 덮어씀 */
```

## subgrid — 격자를 물려받기

[그리드 레이아웃](/posts/css-layout)의 아쉬움이었습니다. 카드 안의 요소들을 **바깥 그리드 선에 맞추고** 싶은데 방법이 없었죠.

```css
.cards { display: grid; grid-template-rows: auto 1fr auto; }
.card {
  display: grid;
  grid-template-rows: subgrid;   /* 부모의 행을 그대로 사용 */
  grid-row: span 3;
}
```

이제 카드마다 제목 길이가 달라도 **모든 카드의 본문과 버튼이 같은 줄에서 시작**합니다. 예전엔 자바스크립트로 높이를 재서 맞추던 일이에요.

## 그 밖에

- **`aspect-ratio`** — 비율 유지. [이미지 밀림 방지](/posts/image-optimization)의 핵심
- **`clamp()`** — `font-size: clamp(1rem, 2.5vw, 1.5rem)`으로 반응형 타이포그래피를 한 줄에
- **`gap`** — 이제 flexbox에서도 동작. 마진 해킹 종료
- **`color-mix()`** — 색을 CSS에서 섞어 파생 색상 만들기

---

최근 CSS의 변화는 "**우회하던 것을 정면으로 하게 됐다**"로 요약됩니다. 부모 선택은 `:has()`로, 중첩은 네이티브로, 명시도 싸움은 `@layer`로, 높이 맞추기는 `subgrid`로 — 자바스크립트나 전처리기로 때우던 자리들이 하나씩 CSS로 돌아오고 있어요. 도구를 덜 쓰고도 더 잘할 수 있게 된 셈입니다.
