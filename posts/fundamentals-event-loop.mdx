JavaScript는 **싱글 스레드**입니다. 한 번에 한 가지 코드만 실행합니다. 그런데 웹 페이지는 서버 응답을 기다리는 동안에도 버튼이 눌리고, 타이머도 동작하고, 애니메이션도 돌아갑니다. 한 번에 하나만 하는데 어떻게 이게 가능할까요? 그리고 면접 단골 문제인 이 코드는 왜 이 순서로 찍힐까요?

```js
console.log(1);
setTimeout(() => console.log(2), 0);
Promise.resolve().then(() => console.log(3));
console.log(4);
// 출력: 1 → 4 → 3 → 2
```

## 기다리는 일은 JavaScript가 하지 않는다

핵심은 **기다리는 일을 JavaScript 엔진이 직접 하지 않는다**는 점입니다.

- `setTimeout`의 시간 재기
- `fetch`의 네트워크 통신
- 클릭 같은 사용자 입력 감지

이런 일은 **브라우저**(Node.js라면 런타임)가 맡습니다. JavaScript는 "1초 뒤에 이 함수 실행해 줘", "응답 오면 이 함수 실행해 줘"라고 **맡겨 두고 바로 다음 코드로** 넘어갑니다. 기다리는 일이 끝나면 브라우저는 그 콜백을 **대기 줄(큐)** 에 세워 둡니다.

그리고 JavaScript가 지금 하던 일을 다 끝내면, 대기 줄에서 다음 콜백을 꺼내 실행합니다. 이 "하던 일 끝내기 → 줄에서 다음 일 꺼내기"를 끝없이 반복하는 구조가 **이벤트 루프**입니다.

## 등장인물

| 이름 | 역할 |
| --- | --- |
| 콜 스택 | 지금 실행 중인 함수들이 쌓이는 곳. JavaScript는 여기 있는 것만 실행함 |
| 태스크 큐 | setTimeout, 클릭 같은 이벤트, 네트워크 콜백 등이 기다리는 줄 |
| 마이크로태스크 큐 | Promise의 then·catch·finally, await 이후 코드, queueMicrotask가 기다리는 줄 |
| 이벤트 루프 | 콜 스택이 비면 큐에서 다음 일을 꺼내 콜 스택에 올리는 반복 |

## 이벤트 루프가 도는 순서

한 바퀴는 이렇게 돕니다.

1. **태스크 하나**를 꺼내 실행합니다. (처음에는 스크립트 전체가 하나의 태스크입니다.)
2. 콜 스택이 비면 **마이크로태스크 큐가 빌 때까지 전부** 실행합니다. 실행 중에 새 마이크로태스크가 생기면 그것까지 실행합니다.
3. 필요하면 **화면을 다시 그립니다.** (requestAnimationFrame 콜백도 이때 실행됩니다.)
4. 다시 1번으로 갑니다.

여기서 가장 중요한 비대칭이 있습니다.

> 태스크는 **한 바퀴에 하나**, 마이크로태스크는 **한 번에 전부**.

## 처음 문제를 따라가 보기

```js
console.log(1);
setTimeout(() => console.log(2), 0);
Promise.resolve().then(() => console.log(3));
console.log(4);
```

1. 스크립트 실행(태스크) 시작. `1` 출력.
2. `setTimeout`: 브라우저에 맡김. 0ms가 지나면 콜백이 **태스크 큐**로.
3. `Promise.resolve().then(...)`: 이미 resolve된 Promise라서 콜백이 바로 **마이크로태스크 큐**로.
4. `4` 출력. 스크립트 태스크 끝, 콜 스택이 빔.
5. 마이크로태스크 큐를 전부 실행: `3` 출력.
6. (화면 그리기)
7. 다음 태스크: `2` 출력.

`setTimeout(fn, 0)`은 "0ms 뒤 실행"이 아니라 **"다음 태스크로 예약"** 입니다. 그래서 지금 스크립트가 끝나고, 마이크로태스크까지 다 끝난 뒤에야 실행됩니다.

## 조금 더 복잡한 예

```js
console.log("start");
setTimeout(() => console.log("timeout"), 0);
Promise.resolve()
  .then(() => console.log("promise 1"))
  .then(() => console.log("promise 2"));
queueMicrotask(() => console.log("microtask"));
console.log("end");
// 출력: start → end → promise 1 → microtask → promise 2 → timeout
```

- 마이크로태스크 큐에는 처음에 `promise 1`과 `microtask`가 들어 있습니다.
- `promise 1`이 실행되면서 다음 `then`(`promise 2`)이 **그때** 큐 뒤에 붙습니다.
- 그래서 `microtask`가 먼저, `promise 2`가 그다음입니다.
- 마이크로태스크가 모두 끝나야 `timeout` 태스크가 실행됩니다.

## await 뒤의 코드는 마이크로태스크다

```js
async function run() {
  console.log("A");
  await null;
  console.log("B");
}

console.log("start");
run();
Promise.resolve().then(() => console.log("C"));
console.log("end");
// 출력: start → A → end → B → C
```

`async` 함수는 **첫 `await`까지는 그냥 동기로** 실행됩니다. 그래서 `A`가 `end`보다 먼저 나옵니다. `await` 뒤의 코드(`B`)는 마이크로태스크로 예약되고, 그보다 나중에 예약된 `C`보다 먼저 실행됩니다.

## 태스크 사이에는 항상 마이크로태스크가 끼어든다

```js
setTimeout(() => {
  console.log("timeout 1");
  Promise.resolve().then(() => console.log("promise in timeout 1"));
}, 0);
setTimeout(() => console.log("timeout 2"), 0);
// 출력: timeout 1 → promise in timeout 1 → timeout 2
```

`timeout 1` 태스크가 끝나면, 다음 태스크로 가기 전에 **그 사이에 생긴 마이크로태스크를 먼저** 비웁니다.

## 왜 Promise를 먼저 실행하도록 만들었을까

마이크로태스크는 "지금 하던 일의 **바로 뒷정리**"를 위한 줄입니다. Promise 결과를 이어서 처리하는 코드는 지금 작업과 이어지는 일이라서, 그 사이에 클릭 이벤트나 다른 타이머가 끼어들면 상태가 어긋날 수 있습니다. 그래서 **현재 작업 → 그 뒷정리(마이크로태스크) 전부 → 화면 그리기 → 다음 작업** 순서로, 한 작업의 결과가 화면에 반영되기 전에 일관된 상태가 되도록 설계했습니다.

## 실무에서 주의할 점

### 긴 작업은 모든 것을 멈춘다

콜 스택이 비어야 다음 일을 할 수 있으니, 오래 걸리는 동기 코드 하나가 실행되는 동안에는 **클릭도, 화면 그리기도 멈춥니다.** Core Web Vitals의 INP(입력 후 화면이 반응하기까지의 시간)가 나빠지는 가장 흔한 이유입니다.

- 큰 반복 작업은 잘게 나눠서 태스크 사이에 숨 쉴 틈을 줍니다. (`setTimeout`으로 나누거나, 지원하는 브라우저에서는 `scheduler.yield()`를 씁니다.)
- 정말 무거운 계산은 Web Worker로 메인 스레드 밖에서 실행합니다.

### 마이크로태스크도 무한히 쌓으면 화면이 멈춘다

마이크로태스크는 "전부 비울 때까지" 실행합니다. 마이크로태스크 안에서 계속 새 마이크로태스크를 만들면 큐가 영영 비지 않아서, 화면 그리기 단계로 넘어가지 못하고 페이지가 멈춥니다.

### setTimeout은 정확한 타이머가 아니다

`setTimeout(fn, 100)`은 "100ms 뒤에 **큐에 넣는다**"이지 "100ms 뒤에 실행한다"가 아닙니다. 그때 콜 스택이 바쁘면 더 늦어집니다. 또 브라우저는 중첩된 타이머의 최소 지연을 4ms로 늘리고, 백그라운드 탭의 타이머는 더 느리게 돌립니다.

### 애니메이션은 requestAnimationFrame으로

`requestAnimationFrame` 콜백은 **화면을 그리기 직전**에 실행됩니다. setTimeout으로 애니메이션을 만들면 화면 그리기 시점과 어긋나 끊겨 보일 수 있습니다.

## 정리

| 줄 | 들어가는 것 | 실행 방식 |
| --- | --- | --- |
| 태스크 큐 | setTimeout, setInterval, 이벤트, 네트워크 콜백 | 한 바퀴에 하나 |
| 마이크로태스크 큐 | Promise then·catch·finally, await 이후, queueMicrotask | 태스크가 끝날 때마다 전부 |
| 렌더링 | requestAnimationFrame, 스타일·레이아웃·페인트 | 마이크로태스크 다음, 필요할 때 |

> "JavaScript는 싱글 스레드라 한 번에 하나만 실행하지만, 기다리는 일은 브라우저에 맡기고 끝나면 콜백을 큐에 넣습니다. 이벤트 루프는 콜 스택이 비면 태스크 하나를 실행하고, 그다음 마이크로태스크 큐를 전부 비우고, 필요하면 화면을 그린 뒤 다음 태스크로 넘어갑니다. Promise 콜백은 마이크로태스크라서 setTimeout 같은 태스크보다 먼저 실행되고, 긴 동기 작업은 이 반복 전체를 막아 입력과 화면 갱신을 멈추게 합니다."
