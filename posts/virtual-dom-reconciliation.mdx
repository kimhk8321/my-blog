[입문 글](/posts/modern-react-intro)에서 "React는 Virtual DOM으로 차이만 실제 DOM에 반영한다"고 했습니다. 그 '차이를 찾는' 과정이 **재조정(reconciliation)** 입니다. 이걸 이해하면 `key` 경고가 왜 그렇게 중요한지, 왜 배열 인덱스를 key로 쓰면 버그가 나는지가 명확해집니다.

## 왜 가상 DOM인가

실제 DOM 조작은 느립니다(레이아웃·페인트 유발, [브라우저 렌더링 과정](/posts/js-deep-dive-browser-rendering) 참고). React는 렌더 결과를 **가벼운 자바스크립트 객체 트리**(가상 DOM)로 만들고, 이전 트리와 비교해 **바뀐 부분만** 실제 DOM에 적용합니다.

두 트리를 완벽히 비교하는 건 O(n³)입니다. React는 두 가지 **휴리스틱**으로 이를 O(n)으로 줄입니다.

## 재조정의 두 규칙

### 1. 타입이 다르면 통째로 교체

같은 위치의 엘리먼트 타입이 다르면(`<div>` → `<span>`, `ComponentA` → `ComponentB`), 하위 트리를 **버리고 새로 만듭니다.** 그 안의 상태도 사라집니다.

```jsx
// 조건에 따라 타입이 바뀌면 내부 상태가 초기화된다
{isEditing ? <Input /> : <Text />}
```

### 2. 타입이 같으면 속성만 갱신

같은 타입이면 DOM 노드를 **유지**하고 바뀐 속성만 업데이트합니다. 자식은 재귀적으로 같은 규칙을 적용합니다.

## 리스트와 key — 핵심

문제는 **리스트**입니다. 순서가 바뀌거나 중간에 삽입/삭제되면, React는 어떤 항목이 "같은 것"인지 알아야 합니다. 그 신원(identity)이 바로 **`key`** 입니다.

key가 없으면 React는 **위치(인덱스)로 비교**합니다. 그래서 맨 앞에 항목을 추가하면:

```
이전:  [A, B, C]      (인덱스 0,1,2)
이후:  [Z, A, B, C]   (인덱스 0,1,2,3)
```

인덱스 기준 비교라 React는 "0번이 A→Z로 바뀌었고, 1번이 B→A로…" 라고 판단해 **거의 모든 노드를 갱신**합니다. Z 하나 추가했을 뿐인데 말이죠.

### 안정적인 key를 주면

각 항목에 고유 id를 key로 주면, React는 A/B/C가 **그대로 이동**했고 Z만 새로 생겼음을 알아채 **Z만 삽입**합니다.

```jsx
{items.map((item) => (
  <Row key={item.id} item={item} /> // 위치가 아니라 신원으로 비교
))}
```

## 왜 배열 인덱스를 key로 쓰면 안 되나

`key={index}`는 사실상 "위치를 신원으로 쓰는" 것이라 key가 없는 것과 비슷해집니다. 특히 **입력 상태가 있는 리스트**에서 버그가 납니다.

```jsx
// 각 행에 체크박스(내부 상태)가 있는데 index를 key로 쓰면…
{todos.map((todo, index) => <TodoRow key={index} todo={todo} />)}
```

맨 앞 항목을 삭제하면 모든 항목의 인덱스가 한 칸씩 당겨집니다. React는 "0번 위치의 컴포넌트는 유지"라고 보고 **DOM/상태를 재사용**하는데, 실제 데이터는 밀렸으므로 **입력 상태가 엉뚱한 항목에 남습니다.** id를 key로 쓰면 이 문제가 사라집니다.

## 실전 팁 — key로 상태 리셋하기

반대로, key가 바뀌면 컴포넌트가 새로 마운트된다는 성질을 **의도적으로** 쓸 수 있습니다. 예를 들어 선택된 사용자가 바뀔 때 폼을 초기화하려면:

```jsx
<ProfileForm key={userId} user={user} /> // userId가 바뀌면 폼 상태 리셋
```

## 마무리

재조정은 "두 트리 비교를 어떻게 싸면서도 정확하게 할까"에 대한 React의 대답입니다. 타입이 다르면 갈아치우고 같으면 속성만 손보되, 리스트만큼은 key로 각 항목의 신원을 알려줘야 최소한만 바뀝니다. 인덱스를 key로 쓰면 그 신원이 무너져 상태가 엉뚱한 자리에 남는다는 것도 위 데모에서 봤고요.
