정규식은 프론트엔드의 계륵 같은 존재입니다. 이메일 검증, 문자열 파싱, 찾기·바꾸기에 강력하지만, 막상 짜면 맞는지 확신이 안 서죠. 그래서 regex101 같은 **테스터**로 확인하며 다듬습니다. 그 테스터, 사실 직접 만들 수 있습니다 — 그리고 만들다 보면 정규식 엔진이 어떻게 도는지 이해하게 됩니다.

## 핵심 문제 — 매치 위치를 알아내기

`String.match`는 매치된 **문자열**을 주지만, 하이라이트하려면 **어디서부터 어디까지** 매치됐는지(인덱스)가 필요합니다. 이건 `RegExp.exec`를 반복 호출해 얻습니다.

```js
const re = /\w+@\w+\.\w+/g;
let m;
while ((m = re.exec(text)) !== null) {
  console.log(m[0]);      // 매치된 문자열
  console.log(m.index);   // 시작 위치 ← 이게 필요하다
}
```

`g`(global) 플래그가 붙은 정규식은 내부에 **`lastIndex`** 를 유지합니다. `exec`를 부를 때마다 이 위치부터 다음 매치를 찾고, `lastIndex`를 매치 끝으로 옮깁니다. 그래서 `while`로 반복하면 모든 매치를 순회할 수 있죠.

## 하이라이트 — 텍스트를 조각으로 쪼개기

매치 인덱스를 알면, 텍스트를 **"매치 아닌 부분"과 "매치 부분"의 조각들**로 나눌 수 있습니다.

```js
function highlight(text, re) {
  const segs = [];
  let last = 0, m;
  re.lastIndex = 0;
  while ((m = re.exec(text))) {
    if (m.index > last) segs.push({ t: text.slice(last, m.index) }); // 사이 텍스트
    segs.push({ t: m[0], mark: true });                              // 매치
    last = m.index + m[0].length;
    if (!re.global) break;
  }
  if (last < text.length) segs.push({ t: text.slice(last) });        // 나머지
  return segs;
}
```

그리고 조각을 렌더링하며 `mark`인 것만 `<mark>`로 감쌉니다.

```jsx
{segs.map((s, i) => s.mark ? <mark key={i}>{s.t}</mark> : <span key={i}>{s.t}</span>)}
```

## 함정 1 — 제로 길이 매치의 무한 루프

`exec` 반복에는 악명 높은 함정이 있습니다. `a*`, `\b`, `(?=…)` 같은 **길이 0짜리 매치**가 나오면 `lastIndex`가 안 움직여 **무한 루프**에 빠집니다.

```js
if (m[0] === "") re.lastIndex++; // 제로 길이면 강제로 한 칸 전진
```

이 한 줄로 커서를 억지로 밀어 무한 루프를 막습니다. 정규식 테스터가 안 멈추고 죽는 대부분의 원인이 이거예요.

## 함정 2 — 잘못된 패턴 방어

사용자가 입력하는 패턴은 언제든 문법 오류일 수 있습니다. `new RegExp`은 잘못된 패턴에 **예외를 던지므로** 반드시 감쌉니다.

```jsx
let error = null, segs = [{ t: text }];
try {
  const re = new RegExp(pattern, flags);
  segs = highlight(text, re).segs;
} catch (e) {
  error = e.message; // "Invalid regular expression: …"
}
```

오류 메시지를 그대로 보여주면, 사용자가 어디가 틀렸는지 바로 압니다.

## 함정 3 — 상태를 가진 정규식

`g` 플래그 정규식은 `lastIndex`라는 **상태**를 갖습니다. 그래서 같은 정규식 객체를 재사용하면 이전 위치부터 찾아 버그가 납니다.

```js
const re = /\d+/g;
re.test("a1");  // true,  lastIndex=2
re.test("a1");  // false! lastIndex가 2라 못 찾음
```

매번 `re.lastIndex = 0`으로 초기화하거나, 필요할 때마다 새로 만드세요. "정규식이 두 번째엔 왜 안 되지?"의 범인이 대개 이겁니다.

---

정규식 테스터를 만들며 배우는 건 정규식 문법이 아니라 **엔진의 동작**입니다. `exec`가 `lastIndex`를 옮기며 훑는다는 것, 제로 길이 매치가 커서를 안 옮긴다는 것, `g` 플래그가 상태를 가진다는 것 — 이걸 알면 정규식이 "안 되는" 순간에 당황하지 않습니다. 다음 글에서는 접근성을 갖춘 [자동완성 콤보박스](/posts/accessible-combobox)를 만듭니다.
