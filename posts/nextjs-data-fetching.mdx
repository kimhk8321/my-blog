[App Router](/posts/nextjs-app-router)·[RSC](/posts/react-server-components)에 이어, Next.js에서 데이터를 가져오고 캐싱하는 방식을 정리합니다.

## 서버 컴포넌트에서 fetch

서버 컴포넌트는 `async`로 만들어 직접 `await fetch` 합니다. 클라이언트의 `useEffect` 패턴이 필요 없습니다.

```tsx
export default async function Page() {
  const res = await fetch("https://api.example.com/posts");
  const posts = await res.json();
  return <PostList posts={posts} />;
}
```

## 캐싱 — 기본은 캐시 안 함

한때 App Router의 `fetch`는 **기본으로 캐시**됐지만, **Next.js 16부터는 반대**입니다. `fetch`는 기본적으로 캐시되지 않고 매 요청마다 새로 가져옵니다. 예측 가능해진 대신, 캐시가 필요하면 **직접 선언**해야 하죠.

```tsx
// 기본 — 캐시 안 함 (매 요청마다 새로)
const posts = await fetch(url).then((r) => r.json());
```

캐시하려면 **`use cache`** 지시어로 함수나 컴포넌트의 반환값을 캐시합니다. 수명은 `cacheLife`, 무효화용 태그는 `cacheTag`로 붙입니다.

```tsx
import { cacheLife, cacheTag } from "next/cache";

async function getPosts() {
  "use cache";
  cacheLife("hours"); // 얼마나 살아있을지
  cacheTag("posts");  // 무효화용 태그
  return db.query("SELECT * FROM posts");
}
```

데이터를 바꾼 뒤엔 `revalidateTag("posts")`로 그 캐시만 지웁니다. 반대로 **매번 신선해야 하는 데이터**는 캐시하지 말고 `<Suspense>`로 감싸 스트리밍하죠.

> 캐싱 모델은 Next.js 16에서 크게 바뀌었습니다. `use cache`·`cacheLife`·태그 무효화·스트리밍의 자세한 내용은 [Next.js 16 캐싱](/posts/nextjs-caching) 글에서 다룹니다. 정적/동적 렌더링의 큰 그림은 [렌더링 전략](/posts/ssr-rendering)과 연결됩니다.

## Server Actions — 변경 처리

폼 제출 같은 **데이터 변경**을 별도 API 라우트 없이 서버 함수로 처리합니다. 함수 상단에 `"use server"`를 붙입니다.

```tsx
// app/posts/actions.ts
"use server";
import { revalidatePath } from "next/cache";

export async function createPost(formData: FormData) {
  const title = formData.get("title");
  await db.post.create({ data: { title } });
  revalidatePath("/posts"); // 목록 페이지 캐시 갱신
}
```

```tsx
// 폼에서 직접 사용
import { createPost } from "./actions";

export default function NewPost() {
  return (
    <form action={createPost}>
      <input name="title" />
      <button type="submit">작성</button>
    </form>
  );
}
```

> 인증·`useActionState`·낙관적 업데이트 등 서버 액션의 실전 패턴은 [Server Actions](/posts/nextjs-server-actions) 글에서 더 깊이 다룹니다.

## 클라이언트에서의 패칭

상호작용 중 발생하는 패칭(무한 스크롤, 실시간 등)은 여전히 클라이언트에서 합니다. 이때는 [React Query](/posts/react-query)를 쓰면 캐싱·리페치를 깔끔하게 다룰 수 있습니다.

---

App Router의 데이터 흐름은 "**읽기는 서버 컴포넌트의 `fetch`, 캐싱은 `use cache`로 명시, 변경은 Server Actions**"로 요약됩니다. 무엇을 캐시하고 무엇을 스트리밍할지만 정하면 정적의 속도와 동적의 신선함을 상황에 맞게 조합할 수 있습니다.
