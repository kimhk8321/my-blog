이분 탐색은 코드가 짧아서 오히려 외우기 쉽습니다. 그런데 `left = mid`인지 `mid + 1`인지 헷갈리기 시작하면 작은 입력에서 무한 루프가 납니다. 경계의 뜻을 먼저 정해 보겠습니다.

## 처음으로 target 이상인 위치

오름차순 배열에서 target 이상인 첫 위치를 찾습니다. 그런 값이 없으면 배열 길이를 반환합니다. 중복이 있어도 가장 왼쪽 위치가 필요합니다.

```js
function lowerBound(nums, target) {
  let left = 0;
  let right = nums.length;

  while (left < right) {
    const mid = left + Math.floor((right - left) / 2);
    if (nums[mid] >= target) right = mid;
    else left = mid + 1;
  }
  return left;
}

console.log(lowerBound([1, 2, 2, 2, 5], 2));
console.log(lowerBound([1, 2, 2, 2, 5], 6));
console.log(lowerBound([], 3));
```

결과는 `1`, `5`, `0`입니다. 검사할 원소 구간은 `[left, right)`이고, 정답인 경계는 right와 같을 수도 있습니다. left 앞은 모두 target 미만이고, right부터는 모두 target 이상이라는 조건을 유지합니다. `right === nums.length`는 끝을 나타내는 경계라 실제 원소를 읽지 않습니다.

중간값이 조건을 만족해도 더 왼쪽 답이 있을 수 있어 `right = mid`로 남깁니다. 만족하지 않으면 mid 자체는 답이 아니므로 `left = mid + 1`로 버립니다. 매번 구간이 줄어들어 시간 O(log n), 추가 공간 O(1)입니다.

## 값 하나 찾기와 경계 찾기는 다르다

target보다 **큰** 첫 위치는 비교 하나가 달라집니다.

```js
function upperBound(nums, target) {
  let left = 0;
  let right = nums.length;
  while (left < right) {
    const mid = left + Math.floor((right - left) / 2);
    if (nums[mid] > target) right = mid;
    else left = mid + 1;
  }
  return left;
}

const sorted = [1, 2, 2, 2, 5];
console.log(upperBound(sorted, 2) - lowerBound(sorted, 2));
```

두 경계의 차이가 target의 개수이므로 결과는 3입니다. 정렬되지 않은 배열에서는 이 논리가 성립하지 않습니다. 정렬 비용도 전체 풀이에 포함해야 합니다.

숫자 정렬은 `[...nums].sort((a, b) => a - b)`처럼 비교 함수를 넣습니다. 기본 `sort()`는 문자열 기준이고 원본도 변경합니다. 엔진별 정렬 복잡도는 명세가 고정하지 않으므로, 코딩테스트에서는 보통 O(n log n) 정렬을 가정한다고 밝혀 두는 편이 낫습니다. [MDN sort 문서](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/sort)에 이 차이가 정리돼 있습니다.

## 배열이 없어도 정답을 이분 탐색할 수 있다

양의 정수 무게를 가진 상자를 순서대로 운반합니다. 한 번 싣는 총무게는 용량 이하이고, 상자를 쪼개거나 순서를 바꿀 수 없습니다. 주어진 일수 안에 전부 운반할 최소 정수 용량을 구합니다. days는 1 이상입니다.

용량이 충분한지 확인하는 함수는 한 번 순회로 만들 수 있습니다. 용량을 늘렸다고 운반이 불가능해지지는 않습니다. 가능한 용량이 **거짓, 거짓, 참, 참**으로 바뀌므로 첫 참을 찾습니다.

```js
function minShipCapacity(weights, days) {
  if (weights.length === 0) return 0;
  let left = 0;
  let right = 0;
  for (const weight of weights) {
    left = Math.max(left, weight);
    right += weight;
  }

  function canShip(capacity) {
    let usedDays = 1;
    let load = 0;
    for (const weight of weights) {
      if (load + weight > capacity) {
        usedDays++;
        load = 0;
      }
      load += weight;
    }
    return usedDays <= days;
  }

  while (left < right) {
    const mid = left + Math.floor((right - left) / 2);
    if (canShip(mid)) right = mid;
    else left = mid + 1;
  }
  return left;
}

console.log(minShipCapacity([1, 2, 3, 4, 5], 3));
```

답은 6입니다. `[1, 2, 3]`, `[4]`, `[5]`로 운반합니다. 하한은 가장 무거운 상자, 상한은 전체 합입니다. 상한은 하루에 전부 싣는 값이라 반드시 가능합니다. 최대 무게보다 작은 후보를 검사하지 않으므로 `canShip()` 안에서 상자 하나가 용량을 초과하는 경우는 없습니다.

무게 합이 S, 가장 무거운 값이 M이면 O(n log(S - M + 1)) 정도의 시간과 O(1) 추가 공간을 씁니다. 탐색 범위가 하나뿐인 경우에도 초기 순회 O(n)은 필요합니다. 이 글의 정수 계산은 합이 `Number.MAX_SAFE_INTEGER` 이내라는 전제입니다. 범위를 넘는 문제에서는 `BigInt`와 정수 나눗셈으로 옮겨야 합니다. 비트 연산으로 중간값을 줄이는 습관도 32비트 변환 때문에 피합니다.

## 종료 조건보다 먼저 적을 것

빈 배열, 모든 값이 같은 배열, target이 최솟값보다 작거나 최댓값보다 큰 경우를 확인합니다. 정답 범위 탐색에서는 “후보가 커질수록 가능성이 한 방향으로만 바뀌는가?”와 “상한이 실제로 가능한가?”를 별도로 확인합니다.

이분 탐색은 절반을 버려도 정답이 남는다는 근거가 있어야 합니다. 그 근거를 설명하지 못하면 코드를 먼저 작성하지 않는 편이 낫겠습니다. [경계와 임의 조건 탐색 설명](https://cp-algorithms.com/num_methods/binary_search.html)도 함께 참고했습니다.
