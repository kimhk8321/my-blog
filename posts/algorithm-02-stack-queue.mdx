괄호가 닫힐 때는 가장 최근에 열린 괄호와 짝을 맞춰야 합니다. 반면 대기열에서는 먼저 들어온 요청부터 처리합니다. 둘 다 배열에 값을 담지만, **어디에서 꺼내느냐**가 문제의 의미를 바꿉니다.

## 괄호 검사에서 스택에 남는 것은 무엇인가

입력은 `()[]{}`로만 이루어진 문자열이라고 정하겠습니다. 올바르게 중첩된 괄호인지 확인합니다. 빈 문자열은 올바른 것으로 처리합니다.

```js
function isBalanced(text) {
  const stack = [];
  const pairs = new Map([[")", "("], ["]", "["], ["}", "{"]]);
  const opens = new Set(["(", "[", "{"]);

  for (const char of text) {
    if (opens.has(char)) {
      stack.push(char);
    } else if (!pairs.has(char) || stack.pop() !== pairs.get(char)) {
      return false;
    }
  }
  return stack.length === 0;
}

console.log(isBalanced("([]){}"));
console.log(isBalanced("([)]"));
console.log(isBalanced("(("));
```

스택에는 **아직 닫히지 않은 여는 괄호**가 순서대로 남습니다. 닫는 괄호가 왔을 때 맨 위와 다르면 바로 실패입니다. 모든 문자를 읽은 뒤에도 스택이 비어야 합니다. 끝의 검사를 빼면 `((`를 통과시킵니다.

각 문자는 한 번 넣고 최대 한 번 뺍니다. 시간 O(n), 최대 깊이만큼 공간을 사용하므로 최악 O(n)입니다. 괄호 종류가 하나라면 개수만 셀 수 있지만 여러 종류에서는 순서까지 기억해야 합니다.

## 큐는 배열 앞부분을 매번 지울 필요가 없다

JavaScript에서 `push()`와 `shift()`로 큐를 만들기는 쉽습니다. 하지만 큰 큐에서 앞 원소를 매번 제거하면 뒤쪽 인덱스 정리에 비용이 들 수 있어, 선형 시간 풀이의 전제가 깨질 수 있습니다. 코딩테스트에서는 보통 읽을 위치를 따로 둡니다.

```js
class Queue {
  constructor() {
    this.items = [];
    this.head = 0;
  }
  get size() {
    return this.items.length - this.head;
  }
  enqueue(value) {
    this.items.push(value);
  }
  dequeue() {
    if (this.size === 0) return undefined;
    const value = this.items[this.head];
    this.items[this.head++] = undefined;
    return value;
  }
}

const queue = new Queue();
queue.enqueue("A");
queue.enqueue("B");
console.log(queue.dequeue(), queue.dequeue(), queue.size);
```

앞에서 읽은 슬롯은 비워 참조를 해제하지만 배열 길이는 줄어들지 않습니다. 이 구현의 보관 공간은 현재 대기 수가 아니라 **누적 enqueue 횟수**에 비례합니다. 한 번의 BFS에서는 O(V)라 충분하지만, 계속 살아 있는 서버 큐라면 원형 버퍼나 주기적인 압축을 고려해야 합니다. `undefined`도 데이터로 허용한다면 빈 큐 여부는 반환값 대신 `size`로 구분합니다.

## 다음 큰 수: 아직 답을 못 찾은 인덱스를 쌓는다

각 원소 오른쪽에서 처음 등장하는 더 큰 값을 구합니다. 없으면 `-1`입니다. `[2, 1, 2, 4, 3]`의 답은 `[4, 2, 4, -1, -1]`입니다.

각 위치마다 오른쪽을 다시 훑으면 O(n²)입니다. 대신 아직 답이 없는 위치를 스택에 두고, 새로운 값이 왔을 때 해결할 수 있는 위치들을 꺼냅니다.

```js
function nextGreater(nums) {
  const answer = Array(nums.length).fill(-1);
  const stack = [];

  for (let i = 0; i < nums.length; i++) {
    while (stack.length > 0 && nums[stack[stack.length - 1]] < nums[i]) {
      answer[stack.pop()] = nums[i];
    }
    stack.push(i);
  }
  return answer;
}

console.log(nextGreater([2, 1, 2, 4, 3]));
```

| 새 값 | 처리 | 스택에 남은 값 |
| --- | --- | --- |
| 2 | 기다림 | 2 |
| 1 | 기다림 | 2, 1 |
| 2 | 1의 답이 2 | 2, 2 |
| 4 | 두 2의 답이 4 | 4 |
| 3 | 기다림 | 4, 3 |

스택의 값은 아래에서 위로 감소하거나 같습니다. 같은 값은 “더 큰 값”이 아니므로 꺼내지 않습니다. 비교를 `<=`로 바꾸면 다른 문제를 풀게 됩니다.

`for` 안에 `while`이 있어도 O(n)입니다. 하나의 인덱스는 한 번 들어가고 한 번만 나올 수 있기 때문입니다. 특정 단계가 비싸더라도 전체 push·pop 횟수는 각각 n번 이하입니다. 추가 공간은 O(n)입니다.

## 작은 입력에서 먼저 확인할 것

괄호는 `")("`, `"([)]"`, `""`를 확인합니다. 다음 큰 수는 증가 배열, 감소 배열, 같은 값만 있는 배열을 확인합니다. 감소 배열에서는 스택이 끝까지 남는 게 정상이고, 같은 값만 있으면 답은 모두 `-1`입니다.

스택 문제에서 막히면 “지금 저장한 값은 어떤 미해결 상태인가?”를 먼저 적어 보면 좋습니다. 다음 [투 포인터·윈도우 편](/posts/algorithm-03-two-pointers)에서는 대기 중인 위치 대신 연속 구간을 유지하겠습니다.

관련 API 동작은 [MDN Array.shift](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/shift)에서 확인할 수 있습니다.
