요즘 실무에서 `class`를 쓰다 보면 JavaScript도 Java 같은 클래스 언어처럼 느껴집니다. 그런데 면접에서 "JavaScript는 프로토타입 기반 언어입니다"라고 답한 뒤 "그럼 클래스 기반 언어와 정확히 뭐가 다른가요?"라는 질문을 받으면 막히기 쉽습니다. 이번 글은 그 질문에 답할 수 있도록 **두 방식이 객체를 만들고, 메서드를 찾고, 상속하는 방법**을 처음부터 비교합니다.

## 클래스 기반 언어: 설계도를 먼저 만든다

Java 같은 클래스 기반 언어에서 객체는 반드시 **클래스라는 설계도**에서 만들어집니다.

```java
class Dog {
    String name;
    Dog(String name) { this.name = name; }
    void bark() { System.out.println(name + ": 멍멍"); }
}

Dog dog = new Dog("초코");
dog.bark();
```

이 방식의 특징은 이렇습니다.

- **구조가 먼저 정해진다.** 어떤 필드와 메서드가 있는지는 클래스에 적은 대로 고정됩니다. 실행 중에 `Dog` 클래스에 메서드를 새로 끼워 넣을 수 없습니다.
- **객체는 클래스의 인스턴스다.** `dog`는 "Dog 타입의 객체"이고, 이 관계는 바뀌지 않습니다.
- **상속은 클래스와 클래스의 관계다.** `class Puppy extends Dog`처럼 설계도가 설계도를 물려받습니다.

## 프로토타입 기반 언어: 객체가 다른 객체를 가리킨다

JavaScript에는 원래 설계도라는 개념이 없습니다. 대신 **모든 객체가 다른 객체 하나를 가리키는 숨은 연결**을 갖고 있습니다. 명세에서는 이 연결을 `[[Prototype]]`이라고 부르고, 가리켜지는 객체를 그 객체의 **프로토타입**이라고 합니다.

```js
const animal = {
  speak() {
    return `${this.name}: 소리를 냅니다`;
  },
};

const dog = Object.create(animal); // dog의 [[Prototype]]을 animal로
dog.name = "초코";

console.log(dog.speak()); // 초코: 소리를 냅니다
console.log(Object.hasOwn(dog, "speak")); // false
console.log(Object.getPrototypeOf(dog) === animal); // true
```

`dog`에는 `speak`가 없습니다. 그런데도 호출할 수 있는 이유는 **속성을 찾는 규칙** 때문입니다.

1. `dog` 자신에게 `speak`가 있는지 찾습니다. 없습니다.
2. `dog`의 프로토타입인 `animal`에서 찾습니다. 있습니다. 이걸 실행합니다.
3. 거기에도 없으면 `animal`의 프로토타입(`Object.prototype`)으로, 그다음으로 계속 올라갑니다. 끝(`null`)까지 가도 없으면 `undefined`입니다.

이렇게 프로토타입을 따라 올라가는 연결을 **프로토타입 체인**이라고 합니다. 여기서 가장 중요한 단어는 **위임**입니다. 클래스 언어처럼 메서드를 객체에 복사해 넣는 게 아니라, 없으면 **다른 객체에게 물어보러 가는** 방식입니다.

## 위임이기 때문에 생기는 일

### 실행 중에 바꾸면 모든 객체에 바로 반영된다

```js
const animal = {};
const dog = Object.create(animal);
const cat = Object.create(animal);

animal.sleep = function () {
  return "쿨쿨";
};

console.log(dog.sleep()); // 쿨쿨
console.log(cat.sleep()); // 쿨쿨
```

`dog`와 `cat`을 만든 **뒤에** `animal`에 메서드를 추가했는데도 둘 다 쓸 수 있습니다. 복사가 아니라 그때그때 찾아가기 때문입니다. 클래스 언어에서는 불가능한 일입니다.

### 같은 이름을 자기 자신에 두면 가려진다

```js
const animal = { sound: "..." };
const dog = Object.create(animal);
dog.sound = "멍멍";

console.log(dog.sound); // 멍멍
console.log(animal.sound); // ...
```

`dog` 자신에게 `sound`가 생기면 프로토타입까지 찾으러 가지 않습니다. 이걸 **섀도잉**이라고 합니다. 프로토타입의 값은 그대로입니다.

## 그럼 생성자 함수와 prototype 속성은 무엇인가

`Object.create`만으로는 불편해서, JavaScript는 함수와 `new`로 객체를 찍어 내는 방법을 제공합니다. 여기서 이름 때문에 가장 많이 헷갈립니다.

```js
function Dog(name) {
  this.name = name;
}
Dog.prototype.bark = function () {
  return `${this.name}: 멍멍`;
};

const dog = new Dog("초코");
console.log(dog.bark()); // 초코: 멍멍
console.log(Object.getPrototypeOf(dog) === Dog.prototype); // true
```

| 이름 | 무엇인가 |
| --- | --- |
| `Dog.prototype` | 함수가 갖는 **일반 속성**. `new Dog()`로 만들 객체들이 프로토타입으로 삼을 객체 |
| `[[Prototype]]` | **모든 객체**가 갖는 숨은 연결. `Object.getPrototypeOf()`로 읽음 |

즉 `Dog.prototype`은 "Dog의 프로토타입"이 아니라 **"Dog가 만든 객체들의 프로토타입"** 입니다. `new Dog("초코")`를 실행하면 내부에서 이런 일이 일어납니다.

1. 빈 객체를 만들고, 그 객체의 `[[Prototype]]`을 `Dog.prototype`으로 연결합니다.
2. `Dog` 함수를 실행하면서 `this`를 그 새 객체로 정합니다. 그래서 `this.name = name`이 새 객체에 저장됩니다.
3. 함수가 다른 객체를 반환하지 않으면 그 새 객체를 반환합니다.

`bark`는 `Dog.prototype`에 **하나만** 있고, 모든 강아지 객체가 위임으로 같이 씁니다. 객체를 천 개 만들어도 함수는 하나라 메모리를 아낍니다.

## class는 이 구조 위에 얹은 문법이다

ES2015의 `class`는 새로운 객체 모델이 아니라, **위의 생성자 함수와 프로토타입 구조를 더 읽기 쉽게 쓰는 문법**입니다.

```js
class Dog {
  constructor(name) {
    this.name = name;
  }
  bark() {
    return `${this.name}: 멍멍`;
  }
}

const dog = new Dog("초코");
console.log(typeof Dog); // function
console.log(Object.getPrototypeOf(dog) === Dog.prototype); // true
console.log(Object.hasOwn(Dog.prototype, "bark")); // true
console.log(Object.hasOwn(dog, "bark")); // false
```

- 클래스의 정체는 **함수**입니다.
- 메서드 `bark`는 인스턴스가 아니라 **`Dog.prototype`에** 들어갑니다.
- 인스턴스는 여전히 위임으로 메서드를 찾습니다.

`extends`도 마찬가지로 프로토타입 체인을 이어 주는 문법입니다.

```js
class Animal {
  eat() {
    return "냠냠";
  }
}
class Dog extends Animal {}

const dog = new Dog();
console.log(Object.getPrototypeOf(Dog.prototype) === Animal.prototype); // true
console.log(dog.eat()); // 냠냠
```

`dog` → `Dog.prototype` → `Animal.prototype` → `Object.prototype` → `null` 순서로 찾아 올라갑니다. "클래스가 클래스를 물려받는다"처럼 보이지만, 실제로는 **객체와 객체가 연결된 것**입니다.

### 그래도 단순한 문법 설탕만은 아니다

`class`에는 생성자 함수로는 흉내 내기 어려운 규칙도 있습니다.

| 규칙 | 내용 |
| --- | --- |
| `new` 없이 호출 불가 | `Dog()`처럼 부르면 TypeError |
| 항상 strict mode | 클래스 본문은 자동으로 strict mode |
| 메서드는 열거되지 않음 | `for...in`에 메서드가 나오지 않음 |
| `#private` 필드 | 클래스 밖에서 접근할 수 없는 진짜 비공개 필드. 프로토타입이 아니라 인스턴스마다 따로 있음 |
| 클래스 필드 | `name = "초코"`처럼 쓴 필드는 프로토타입이 아니라 **인스턴스 자신에** 생김 |

## 한눈에 비교

| | 클래스 기반 (Java 등) | 프로토타입 기반 (JavaScript) |
| --- | --- | --- |
| 객체를 만드는 원본 | 클래스(설계도) | 다른 객체(프로토타입) |
| 메서드를 찾는 방법 | 클래스에 정의된 대로 | 자신 → 프로토타입 → … 순서로 위임 |
| 상속 | 클래스가 클래스를 상속 | 객체가 다른 객체에 연결 |
| 실행 중 구조 변경 | 불가능 | 프로토타입을 바꾸면 즉시 모든 객체에 반영 |
| `instanceof`의 의미 | 이 클래스의 인스턴스인가 | `생성자.prototype`이 프로토타입 체인 어딘가에 있는가 |

마지막 줄이 실무에서 은근히 중요합니다. JavaScript의 `instanceof`는 타입을 검사하는 게 아니라 **체인을 따라가며 특정 객체가 있는지** 확인합니다. 그래서 iframe처럼 다른 실행 환경에서 만든 배열은 `arr instanceof Array`가 `false`가 될 수 있고, 배열인지 확인할 때는 `Array.isArray()`를 씁니다.

## 왜 이렇게 만들어졌을까

JavaScript를 만든 브렌던 아이크는 **Self**라는 프로토타입 언어와 **Scheme**에서 많은 영향을 받았습니다. 클래스 없이 객체만으로 구조를 만드는 Self의 방식이 짧은 기간에 만들어야 했던 가벼운 스크립트 언어에 잘 맞았고, 문법은 당시 인기 있던 Java와 비슷하게 보이도록 했습니다. 이름에 Java가 들어가고 `new` 같은 키워드가 있는데 속은 프로토타입인 이유가 여기에 있습니다.

## 실무에서 주의할 점

- **내장 객체의 프로토타입을 고치지 않는다.** `Array.prototype.myFn = ...`처럼 바꾸면 그 페이지의 모든 배열에 영향을 주고, 나중에 표준에 같은 이름이 추가되면 충돌합니다.
- **화살표 함수 클래스 필드는 인스턴스마다 생긴다.** `handleClick = () => {}`는 프로토타입이 아니라 인스턴스 자신에 함수를 만들어서, 객체가 많으면 그만큼 함수도 많아집니다. 대신 `this`가 고정되는 장점이 있습니다. 이 `this` 이야기는 3편에서 다룹니다.
- **`__proto__` 대신 표준 API를 쓴다.** 프로토타입을 읽고 바꿀 때는 `Object.getPrototypeOf`, `Object.setPrototypeOf`, `Object.create`를 씁니다. 이미 만든 객체의 프로토타입을 바꾸는 건 엔진 최적화를 깨뜨려 느려질 수 있어서 피합니다.

## 정리

> "클래스 기반 언어는 설계도인 클래스로 구조를 먼저 정하고 객체를 그 인스턴스로 만들지만, JavaScript는 객체가 다른 객체를 프로토타입으로 가리키고, 자신에게 없는 속성을 프로토타입 체인을 따라 위임해서 찾습니다. class 문법도 생성자 함수와 prototype 객체를 만드는 문법이라, 메서드는 prototype에 하나만 두고 모든 인스턴스가 위임으로 공유합니다."

이 위임 구조를 알고 나면 `instanceof`, 메서드 공유, 클래스 필드의 메모리 차이가 모두 같은 원리로 설명됩니다. 기존 요약은 [모던 자바스크립트 Deep Dive 정리 (2)](/posts/js-deep-dive-objects)에도 있습니다.
