`1234567`을 `1,234,567`로 바꾸려고 정규식을 검색해 본 적 있나요? 아니면 `"2026년 7월 25일"`을 만들려고 `getFullYear()`, `getMonth() + 1`을 조립해 본 적은요? 이런 코드는 대개 **틀립니다** — 특정 로케일에서만요. 독일은 천 단위를 `.`으로, 소수를 `,`로 씁니다. 아랍어는 오른쪽에서 왼쪽으로 읽고요.

브라우저에는 이 모든 걸 아는 **`Intl`** 객체가 이미 들어 있습니다. 로케일별 규칙을 우리가 알 필요 없이, 넘기기만 하면 됩니다.

## 숫자와 통화 — NumberFormat

`Intl.NumberFormat`은 천 단위 구분, 소수 자릿수, 통화, 퍼센트, 단위를 로케일에 맞게 포맷합니다.

```js
new Intl.NumberFormat("ko-KR").format(1234567.89);
// "1,234,567.89"

new Intl.NumberFormat("de-DE").format(1234567.89);
// "1.234.567,89"  ← 구분자가 반대!

new Intl.NumberFormat("ko-KR", { style: "currency", currency: "KRW" }).format(15000);
// "₩15,000"

new Intl.NumberFormat("en-US", { style: "unit", unit: "kilometer-per-hour" }).format(80);
// "80 km/h"
```

같은 숫자인데 `ko-KR`과 `de-DE`의 결과가 다른 걸 보세요. 손으로 `replace`를 짰다면 독일 사용자에게 깨진 숫자를 보여줬을 겁니다.

## 날짜와 시간 — DateTimeFormat

```js
const d = new Date("2026-07-25T15:30:00");

new Intl.DateTimeFormat("ko-KR", { dateStyle: "full" }).format(d);
// "2026년 7월 25일 토요일"

new Intl.DateTimeFormat("en-US", { dateStyle: "medium", timeStyle: "short" }).format(d);
// "Jul 25, 2026, 3:30 PM"
```

`dateStyle`/`timeStyle`의 `full`·`long`·`medium`·`short` 프리셋만 알아도 대부분 해결됩니다. 세밀하게는 `year`·`month`·`weekday` 등을 개별 지정할 수 있고요.

## 상대 시간 — RelativeTimeFormat

"3일 전", "in 2 hours" 같은 표현은 직접 만들기 특히 까다롭습니다(단수/복수, 언어별 어순). `RelativeTimeFormat`이 해결합니다.

```js
const rtf = new Intl.RelativeTimeFormat("ko-KR", { numeric: "auto" });
rtf.format(-3, "day");  // "3일 전"
rtf.format(1, "day");   // "내일"  ← numeric:"auto"라 '1일 후'가 아님
rtf.format(-2, "hour"); // "2시간 전"
```

## 복수형과 정렬 — 자주 잊는 두 가지

**복수형(PluralRules)**: 영어는 1이면 단수, 나머지 복수지만, 언어마다 규칙이 다릅니다(러시아어는 형태가 셋). 하드코딩하면 틀립니다.

```js
const pr = new Intl.PluralRules("en-US");
pr.select(1);  // "one"  → "1 item"
pr.select(5);  // "other" → "5 items"
```

**정렬(Collator)**: 문자열 정렬을 `<`로 하면 로케일을 무시해 엉뚱한 순서가 됩니다. 한글 자모, 대소문자, 악센트를 제대로 정렬하려면 `Intl.Collator`를 씁니다.

```js
["가", "나", "다"].sort(new Intl.Collator("ko").compare);
["é", "a", "z"].sort(new Intl.Collator("fr").compare); // 악센트 올바르게 처리
```

## 성능 팁 — 포매터를 재사용하라

`Intl.NumberFormat` 같은 포매터 **생성은 비쌉니다**(로케일 데이터 로딩). 리스트를 순회하며 매번 `new`로 만들면 느려집니다. **한 번 만들어 재사용**하세요.

```js
// 나쁨: 1000개 행마다 포매터 생성
rows.map((r) => new Intl.NumberFormat("ko-KR").format(r.price));

// 좋음: 한 번 만들고 재사용
const fmt = new Intl.NumberFormat("ko-KR");
rows.map((r) => fmt.format(r.price));
```

## i18n 라이브러리와의 관계

`react-i18next` 같은 라이브러리는 **번역 문자열 관리**(키→문장, 언어 파일)를 담당합니다. 반면 **숫자·날짜·복수형 포맷**은 그 라이브러리들도 내부적으로 `Intl`에 위임합니다. 즉 번역은 라이브러리, 포맷은 `Intl` — 역할이 다릅니다. 포맷을 직접 조립하는 코드를 봤다면 십중팔구 `Intl`로 대체할 수 있습니다.
