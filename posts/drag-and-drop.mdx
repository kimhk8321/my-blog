드래그 앤 드롭은 쉬워 보이지만, 막상 구현하면 손이 많이 가는 기능입니다. 브라우저에 내장된 **HTML5 Drag and Drop API**가 있긴 한데, 이게 은근히 다루기 까다롭습니다. 커스텀 드래그 이미지가 어색하고, 터치 지원이 빈약하고, 스타일링이 제한적이죠.

그래서 요즘 정렬 가능한 리스트는 대부분 **Pointer Events**로 직접 구현합니다. `pointerdown`/`pointermove`/`pointerup`은 마우스·터치·펜을 하나의 API로 통합해 주기 때문에, 이걸로 짜면 데스크톱과 모바일이 공짜로 함께 해결됩니다.

## 왜 Pointer Events인가

예전엔 마우스는 `mousedown`/`mousemove`, 터치는 `touchstart`/`touchmove`로 따로 처리해야 했습니다. Pointer Events는 이 둘을 통합합니다.

```js
el.addEventListener("pointerdown", start); // 마우스·터치·펜 모두
el.addEventListener("pointermove", move);
el.addEventListener("pointerup", end);
```

여기에 결정적인 기능이 하나 붙습니다 — **포인터 캡처**입니다.

```js
el.setPointerCapture(e.pointerId);
```

이걸 호출하면, 포인터가 그 요소 **밖으로 나가도** 이후의 `pointermove`/`pointerup`이 계속 그 요소로 전달됩니다. 드래그 도중 커서가 항목 경계를 벗어나도 이벤트를 놓치지 않죠. 예전 방식에서 골치였던 "드래그 중 이벤트 유실"이 이 한 줄로 사라집니다.

## 핵심 로직 — 좌표를 인덱스로

드래그 정렬의 본질은 의외로 단순합니다. **"지금 포인터가 몇 번째 항목 위에 있는가"** 를 계산해서, 끌고 있는 항목을 그 자리로 옮기는 것뿐입니다.

```jsx
const ITEM_H = 44; // 항목 하나의 높이
const listRef = useRef(null);
const [dragging, setDragging] = useState(null); // 끌고 있는 항목의 인덱스

function onPointerMove(e) {
  if (dragging === null) return;

  // 리스트 맨 위 기준으로 포인터가 얼마나 내려왔는지
  const rect = listRef.current.getBoundingClientRect();
  const y = e.clientY - rect.top;

  // 높이로 나누면 = 몇 번째 슬롯인지
  let hovered = Math.floor(y / ITEM_H);
  hovered = Math.max(0, Math.min(items.length - 1, hovered));

  // 위치가 바뀌었으면 배열에서 항목을 이동
  if (hovered !== dragging) {
    setItems((prev) => {
      const next = [...prev];
      const [moved] = next.splice(dragging, 1); // 원래 자리에서 빼고
      next.splice(hovered, 0, moved); // 새 자리에 꽂기
      return next;
    });
    setDragging(hovered); // 끌고 있는 인덱스도 갱신
  }
}
```

포인터 Y 좌표를 항목 높이로 나눠 인덱스를 얻고, 그게 바뀔 때마다 배열을 `splice`로 재배열합니다. 실시간으로 순서가 갱신되니 사용자는 항목이 자연스럽게 밀려나는 걸 봅니다.

## 시작과 끝

시작은 `pointerdown`에서 캡처를 걸고 어떤 항목을 잡았는지 기록합니다.

```jsx
function onPointerDown(e, index) {
  e.currentTarget.setPointerCapture(e.pointerId);
  setDragging(index);
}

function stop() {
  setDragging(null); // 드래그 종료 — 캡처는 자동 해제
}
```

`pointerup`뿐 아니라 `pointercancel`(전화가 온다든지 제스처가 가로채질 때)에서도 `stop`을 불러야 드래그가 어정쩡하게 남지 않습니다.

## 순서가 바뀔 때 부드럽게

배열을 `splice`로 재배열하면 항목이 새 자리로 **툭 순간이동**합니다. 이걸 미끄러지게 만드는 흔한 방법은, 각 항목을 문서 흐름에 두지 않고 **`transform: translateY`로 위치를 지정**한 뒤 그 값에 `transition`을 거는 것입니다.

```jsx
{items.map((item, i) => {
  const isDrag = dragging === i;
  // 끌리는 항목은 포인터를 따라가고, 나머지는 자기 슬롯(i)으로
  const y = isDrag ? dragY : i * ROW;
  return (
    <li
      key={item}
      style={{
        transform: `translateY(${y}px)`,
        // 끌리는 항목은 즉시 따라가야 하니 transition 제거
        transition: isDrag ? "none" : "transform 200ms",
      }}
    />
  );
})}
```

포인트는 **위치를 인덱스에서 계산**한다는 겁니다. 배열 순서가 바뀌면 각 항목의 `i`가 바뀌고, `translateY` 목표값이 바뀌니, CSS `transition`이 그 사이를 알아서 보간해 줍니다. 끌고 있는 항목만 `transition: none`으로 두어 포인터에 즉각 반응하게 하고요. 이게 라이브러리들이 쓰는 **FLIP**(위치 차이를 transform으로 애니메이션하는 기법)의 단순화된 형태입니다. ([View Transitions](/posts/view-transitions) 글에서 본 것과 목적이 같습니다 — 위치 변화를 눈으로 따라가게 하기.)

## 실전에서 더 챙길 것들

데모도 여기까진 왔지만, 실제 제품이라면 이런 걸 더합니다.

- **가변 높이**: 항목 높이가 제각각이면 고정 `ITEM_H` 대신 각 요소의 실제 위치를 재야 합니다
- **접근성**: 키보드로도 정렬 가능하게(`aria-grabbed`, 화살표 키 이동) — 마우스 없는 사용자를 위해 필수입니다
- **자동 스크롤**: 긴 리스트에서 위/아래 끝에 닿으면 스크롤

이 지점부터는 `@dnd-kit`이나 `react-movable` 같은 라이브러리가 접근성·엣지 케이스를 잘 처리해 줍니다. 다만 직접 한 번 만들어 보면 그 라이브러리들이 내부에서 무슨 계산을 하는지 훤히 보입니다.
