배열 `[2,1,3]`에서 각 숫자의 오른쪽을 보겠습니다. **자신보다 큰 숫자 중 처음 만나는 숫자**를 찾는 문제입니다.

## 답부터 확인하기

| 현재 값 | 오른쪽에서 확인할 값 | 답 |
| --- | --- | --- |
| 2 | 1은 작고, 3은 큼 | 3 |
| 1 | 바로 다음의 3이 큼 | 3 |
| 3 | 오른쪽에 숫자가 없음 | -1 |

정답은 `[3,3,-1]`입니다. 가장 큰 값을 고르는 문제가 아니라, 오른쪽에서 **먼저 만나는 큰 값**을 찾습니다. 답이 없는 위치는 -1로 표시하겠습니다.

## 오른쪽을 매번 찾는 방법

```js
function nextGreaterSlow(nums) {
  const answer = Array(nums.length).fill(-1);
  for (let i = 0; i < nums.length; i++) {
    for (let j = i + 1; j < nums.length; j++) {
      if (nums[j] > nums[i]) {
        answer[i] = nums[j];
        break;
      }
    }
  }
  return answer;
}
```

이 방식은 이해하기 쉽지만, `[5,4,3,2,1]`에서는 매번 끝까지 찾고도 답이 없습니다. 최악의 시간은 O(n²)입니다.

## 아직 답을 못 찾은 위치만 기다리게 한다

[스택](/posts/algorithm-02-stack-queue)에 넣는 것은 **아직 답이 정해지지 않은 인덱스**입니다. 숫자를 하나 읽을 때마다 그 숫자로 기다리던 위치의 답을 정할 수 있는지 봅니다.

2를 읽으면 아직 오른쪽 숫자를 모르므로 0번을 넣습니다. 1을 읽어도 2보다 작으니 0번의 답을 못 정하고 1번도 넣습니다. 3을 읽으면 1과 2보다 모두 커서 두 위치의 답을 한 번에 정합니다.

| 읽은 숫자 | 하는 일 | 스택의 인덱스 | answer |
| --- | --- | --- | --- |
| 0번의 2 | 0번이 기다림 | `[0]` | `[-1,-1,-1]` |
| 1번의 1 | 1번도 기다림 | `[0,1]` | `[-1,-1,-1]` |
| 2번의 3 | 1번, 0번의 답을 3으로 정함 | `[2]` | `[3,3,-1]` |

값 대신 인덱스를 저장해야 답을 쓸 위치를 알 수 있습니다. 스택 맨 위의 1번을 먼저 해결하고, 그다음 0번도 해결합니다.

## JS 구현

```js
function nextGreater(nums) {
  const answer = Array(nums.length).fill(-1);
  const stack = [];

  for (let i = 0; i < nums.length; i++) {
    while (stack.length > 0) {
      const previous = stack[stack.length - 1];
      if (nums[previous] >= nums[i]) break;
      stack.pop();
      answer[previous] = nums[i];
    }
    stack.push(i);
  }
  return answer;
}

console.log(nextGreater([2, 1, 3]));
```

`previous`는 기다리는 위치, `nums[previous]`는 그 위치의 값입니다. 현재 값이 더 크면 pop하고 답을 기록합니다. 더 크지 않으면 기다리는 상태를 유지하고 while을 끝냅니다.

## 왜 이름이 단조 스택일까?

스택에 남은 위치의 값을 읽으면 바닥부터 위로 작아지거나 같습니다. 새 값보다 작은 값은 먼저 꺼낸 뒤 새 위치를 넣기 때문입니다. 이런 한 방향의 순서를 유지하는 스택을 **단조 스택**이라고 부릅니다.

큰 값이 나왔을 때는 위에서부터 해결할 수 있는 위치를 꺼내기만 하면 됩니다. 그 위치가 여태 남았다는 것은 앞서 더 큰 숫자를 만나지 못했다는 뜻이기도 합니다.

## 반복문이 겹치는데 O(n)인 이유

한 번에 여러 위치를 pop할 수 있지만, **각 위치는 전체 실행에서 한 번 들어가고 최대 한 번 나옵니다.** for마다 모든 원소를 다시 확인하지 않습니다. 그래서 시간 O(n), 공간 O(n)입니다.

`[2,2,3]`의 답도 `[3,3,-1]`입니다. 같은 값은 큰 값이 아니므로 스택에서 꺼내지 않습니다. 입력에 음수가 있어 -1이 실제 답으로도 쓰일 수 있다면, '답 없음'을 null 등으로 구분할지는 문제 조건에 맞춰 정합니다.

스택이 어려울 때는 값이 아니라 **답을 기다리는 위치 목록**이라고 읽어 보겠습니다. 다음 [정답 탐색](/posts/algorithm-advanced-03-parametric-search)에서는 시간 후보를 줄여 갑니다.
